## 2. 게임의 핵심

커서를 이동해 중앙 넥서스를 지키고 생존 시간을 늘리는 세로형 아케이드.

별도 플레이어 대시 기능을 이번 작업에서 되살리지 않는다.
원형 적의 커서형 변형/돌진과 플레이어의 입력 기능을 혼동하지 않는다.

게임의 미적 방향은 기존의 어두운 바탕과 네온 도형 표현을 존중한다.
사용자가 제외한 붉은 테마를 되살리지 않는다. 이것이 모든 피격 강조색 제거를 뜻하지는 않는다.

## 4. 사용자 요청 — 노드와 넥서스

### C-02 원형 공격 — USER_REQUEST
충전 완료 → 회전 테두리가 내부로 빨려들어감 → **전체 원형 본체가 뾰족한 커서 모양으로 변함**

기존 원형 레이저는 제거한다. 본체를 남기고 별도 삼각형 탄을 발사하는 방식으로 대체하지 않는다.
흡수·변형이 자연스럽게 연결되어야 한다. 공격 도중 다른 초기 형태가 잠깐 나타나면 안 된다.

### C-03 원형 사망 — USER_REQUEST / OPEN
충전 중 플레이어가 제거하면 지금처럼 원이 부서지는 폭발 느낌을 유지한다.
돌진 형태의 넥서스 충돌 폭발은 요청되어 있으나 구체적인 파편 형태는 미정이다.
현재 공격 형태에 맞는 커서 파편을 사용하자는 것은 PROPOSAL이다.

### H-01 육각 기본 상태 — USER_REQUEST
현재처럼 게이지가 차는 육각형 본체와 테두리를 유지한다.

### H-02 육각 공격 — USER_REQUEST
충전 완료 → 테두리 내부 흡수 → 육각 본체가 **정삼각형**으로 변함 → 레이저 발사.
원형과 달리 노드 본체가 넥서스로 돌진하지 않는다.
반사된 레이저가 돌아와 삼각형을 타격한 뒤 삼각형이 쪼개지며 터진다.

### H-03 레이저 반환 — USER_REQUEST / OPEN
현재의 “막힌 위치에서 새로운 선이 다시 뻗는 모습”을 없애고,
**이미 발사된 레이저가 방향을 바꿔 돌아오는 모습**으로 표현한다.
정확한 빔 길이·모양·속도·반환 방식은 OPEN이다.
길이가 있는 이동 빔은 PROPOSAL이지 승인된 최종 사양이 아니다.
반사 시점과 노드 도달 시점을 분리하고 실제 반환 도착 전에 파괴하지 않는다.

### COMMON-01 테두리 — USER_REQUEST
두 노드 모두 공격 형태가 되었을 때 장식 테두리가 전부 내부로 흡수되어야 한다.
풀에서 다시 등장하면 원래 도형·테두리·게이지 상태로 완전히 복원한다.

### N-01 넥서스 피격 — USER_REQUEST
레이저가 넥서스 중앙까지 들어간 뒤가 아니라 **넥서스 원의 가장자리**에 닿을 때 피해가 발생한다.
원형 돌진도 같은 가장자리 기준을 사용하자는 것은 일관성을 위한 PROPOSAL이다.
빛 번짐이 아닌 단단한 본체 외곽을 판정 기준으로 삼는 것도 PROPOSAL이며 구현 전 확인한다.
피격 경계가 바뀌면 도달 시간이 달라지므로 자동으로 기존 난이도와 같다고 가정하지 않는다.

### N-02 체력 표현 — USER_REQUEST / PROPOSAL
넥서스 내부가 에너지 액체로 차 있는 느낌이며 피해를 받을 때 자연스럽게 줄어들게 한다.
권장 기술 설계: 논리 체력·사망 판정은 즉시, 표시 수위만 부드럽게 최신 값으로 이동.
실제 유체 시뮬레이션은 요구하지 않았다. 마스크·파형·셰이더는 검토 가능한 수단이다.
연속 피해 때 이전 애니메이션이 최신 체력 표시를 덮어쓰지 않게 한다.

## 5. 튜토리얼·훈련·설정 — 사용자 목표

### T-01 첫 실행 튜토리얼 — USER_REQUEST
첫 시작 때 안내하고, 설정에서 언제든 훈련 공간에 다시 진입할 수 있다.
상단에 원형/육각 생성 버튼을 두고 사용자가 버튼을 눌러 노드를 생성하면서 대응법을 순서대로 배운다.
두 설명이 끝나도 공간을 종료하지 않고 자유 생성·훈련을 이어갈 수 있다.
첫 방문의 정의, 건너뛰기, 중도 종료, 완료 저장 범위는 OPEN이다.

### T-02 훈련장 — USER_REQUEST / PROPOSAL
같은 공간에서 계속 노드를 생성해 연습한다. 아래 설정 패널을 열어 조작감·커서 색상을 조절한다.
권장안: 본 게임과 같은 노드/이동/잔상 코드를 사용하고 생성 정책·안내·기록만 분리한다.
권장안: 정규 기록·업적은 훈련과 분리하고, 학습 보조 속도를 사용하면 실제 속도와 구분 표시한다.
실제 원형 제거/육각 반사 성공을 확인한 후 안내를 넘기는 방식도 PROPOSAL이다.

### T-03 설정 패널 — USER_REQUEST / OPEN
아래쪽 설정 패널을 열고 시험하는 경험이 목표이다. 패널 조작이 게임 입력으로 전달되지 않아야 한다.
패널을 열 때 잠시 정지할지, 상단 플레이를 계속할지 OPEN이다.
모바일에서 패널이 공격·넥서스를 가리는지 확인해야 한다.

### 설정 후보 — 전부 PROPOSAL
| 구분 | 후보 |
|---|---|
| 일반 편의 | 조이스틱 반경, 데드존, 입력 반응 곡선 |
| 표시 | 검증된 커서·잔상 색상, 외곽선 대비 |
| 효과/소리 | 흔들림·섬광·배경 움직임 감소, BGM·SFX 음량 |
| 품질 | 필수 전투 정보는 유지하고 배경·파티클 품질 조정 |
| 개발자 전용 | 최고속도·가속·회전, 잔상 수명/폭, 충전/변형/공격속도, 생성 패턴, HP/피해량 |

기록 경쟁에 영향을 주는 항목은 편의 설정과 구분한다.
보이는 잔상과 실제 방어 구간을 다르게 만들어 유리하게 하는 설정을 기본으로 넣지 않는다.

## 6. 향후 연출과 도구

USER_REQUEST: 밸런스 개발자 모드, 배경, 설정 전환 연출, 리소스 미적 개선, 타격감.
PROPOSAL: 기본 편의 설정은 6단계, 개발자 기능은 2/7단계, UI의 전체 스타일·전환 마감은 8단계.
전투 중 꼭 필요한 UI와 넥서스 HP 표시를 8단계까지 미루지 않는다.
최종적인 웹게임 경쟁력이 목표이나 순위·재미를 문서만으로 보장하지 않는다.

## 7. 기술 선택의 원칙 — PROPOSAL

단순 도형은 기존 스프라이트, 메시 윤곽 보간, 셰이더, DOTween을 비교하여 작은 시제품으로 선택한다.
프레임별 PNG, 새 패키지, 대규모 렌더링 시스템을 먼저 강제하지 않는다.
픽셀아트 제작 도구나 환조 전용 파이프라인은 이 프로젝트의 필수 도구가 아니다.
두 적의 공격 모양과 플레이어 커서는 실루엣·움직임·표식으로 구분 가능하게 한다.
