# 원형 A 외형·중심과 기존 배경 타격감 — D-021

2026-10-25. **구현·정적 확인 완료 / Unity Play·시각 검수 대기.** 사용자가 Unity에서 직접 Play한다는 요청에 따라 Unity 조작·자동 Play·공식 테스트 실행·Unity/WebGL 빌드·커밋·푸시·배포를 하지 않았다. 기존 웹 미리보기는 이번 소스가 아니다.

## 구현한 외형과 보존한 동작

기준은 원본 A의 `Assets/Art/Nodes/Cyberpunk/Types/Cyberpunk_NormalNode/` 부품이다. 새 디자인 대신 실제 Outside PNG의 반알파 윤곽을 .25원본픽셀 이내로 단순화해 **다섯 화살촉 원호**를 벡터 도형으로 옮겼다. 회전 간격·모양·본체 대비 비율을 그대로 따르며 넓은 블러 없이 약 한 화면픽셀의 경계 AA를 사용한다. 원본 PNG/.meta/프리팹을 바꾸지 않았다.

중심은 원호·본체·충전 모두 같은 로컬0이다. 정밀 확인 결과 Outside의 실제 원호 중심은 좌상단 기준 **(100,96.5px)**이고 기존 커스텀 피벗과 일치했다. D-020에서 사용한 전체 경계 상자 중심은 화살촉으로 치우친 값이다. 이를 그대로 적용해 5px 이동시키지 않았다. 본체/충전의 원 맞춤 중심은 각각(53.8796,54.0735)/(70.7622,70.4082)px로, 이 미세 오차를 없애고 공통 반경 **.518279로컬**을 사용했다. 기존 루트.5배/위치·회전축·콜라이더를 이동하지 않았다.

본체 외곽은 #E87CFF, 충전과 회전 테두리는 #CB49FF다. 충전원이 중앙에서 확대되고 회전 원호가 기존 Rotator 각도를 따른다. Warning에서는 원호를 흡수·소멸하고 원래 커서 형태/색으로 부드럽게 이어진다. 최종 커서 꼭짓점과 변형 **.15초 → 반동.05초 → 돌진.20초 / 커서.60배**, 접촉 가능 단계·잔상 방어 불가·앞부분 판정·피해1회·풀 흐름을 유지했다. 돌진 넥서스 충돌 효과와 작은 방향 파편/효과음은 이번에 교체하지 않았다.

위 그림은 원본 PNG 합성과 수정 코드 좌표의 **정적 도형 미리보기**다. Unity 화면 캡처·실제 변형·셰이더 AA 검증 결과가 아니다. 이전 분석의 “네 원호” 오류는 다섯 개로 정정했다.

## 타격감을 바꾼 부분

추가 `WorldCircuitBackdrop`의 자동 생성을 제거했다. 그 기존 코드 파일을 무단 삭제하지는 않았으며 새 Play에서는 추가 회로60개 Mesh를 만들지 않는다.

대신 정확히 **RemakeHUD/Background_Flash**의 기존 Image·스프라이트·RectTransform·색/alpha **87/255**를 읽어 게임 카메라에서 합성한다. 원본 그림을 다시 만들거나 배경을 재디자인하지 않는다. Play 중 이 Image의 UI 표시만 임시 끄고 같은 그림을 카메라가 표시하므로 두 번 그리지 않는다. 해당 소유 효과 컴포넌트를 끄거나 파괴하면 원래 enabled를 복원한다. 색/알파/참조/씬/원화를 저장하지 않는다. 단순 Image가 아닌 아틀라스/미지원 구성이나 셰이더 사용 불가 시 원래 UI 표시를 유지한다.

원형 접촉 제거 한 번에 다음 연출을 함께 요청한다. 게임 판정/제거를 지연시키지 않으며 시간 소유권은 기존 StageManager를 사용한다.

## 조절값과 프리셋

새 슬라이더를 추가하지 않았다. 기존 `fx.circleRemove.*`로 정지/셰이크/렌즈를 조절하며 `visual.outline`(.035)은 원형 본체 외곽선에 적용된다. 회전 원호의 형태는 `CircularNodeOutlineA` 좌표, 충전 팔레트는 `CircularNodeArtwork` 상수다. `circle.color`는 기존 최종 커서색을 유지한다.

`visual.impactExposure`(.65)는 원형에서 원본 Background_Flash의 밝기 마스크 배율이다. 사용자 `user.flash`/`OnFlash`, 렌즈는 `user.distortion`, 전체는 `fx.enabled`를 따른다. 이전 `visual.rippleStrength/Speed/Width`는 육각의 이전 파동용이며 이번 원형에는 쓰지 않는다. 배경 .25초는 새 UI 없이 코드 상수로 두었다.

[원형 전용 changes JSON](examples/circle-originalA-feedback.json)은 이번 수치를 적용하는 **작성 예시**이며 런타임 내보내기/가져오기 검증물은 아니다. 이전 strong/baseline과 사용자 저장·가져온 프리셋은 이전 원형 수치를 적용하므로 새 기본값 비교 시 선택하지 않는다. 기존 프리셋을 덮어쓰거나 삭제하지 않았다.

## Unity 검수 절차

1. 현재 프로젝트에서 코드 자동 반영이 끝나면 Console의 새 컴파일/셰이더 오류를 확인한다. 씬 재생성/전체 저장/전체 TMP 초기화는 필요 없다. 새 셰이더 오류가 있으면 오류 전문을 전달하고 Play를 보류한다.
2. 평소처럼 Play → **훈련**으로 들어간다. 이전 세션 수치가 있다면 먼저 다른 이름으로 내보내 보관하고 **원형 제거 타격 그룹만 복원**한다. 일반 설정/저장 프리셋/최고기록은 지우지 않는다. 기본원형 공격값 .15/.05/.20/.60, `visual.impactExposure`와 섬광/왜곡 켜짐 여부를 확인한다. strong/baseline은 이번 새 기본값과 다른 예전 수치를 적용한다.
3. 기존 생성 버튼으로 원형 하나를 놓고 충전을 본다. **다섯 화살촉 원호·밝은 외곽 원·중앙에서 커지는 진한 충전원**의 비율/회전축이 한 중심에 있는지 확인한다. 작은 독립 중앙점은 없어야 한다.
4. 충전 중 원형에 접촉한다. 기존 작은 방향 파편/소리와 함께 정지→방향 셰이크가 느껴지고, **실제 기존 배경 선이 타격점에서 휘고 잠깐 밝아졌다가** 돌아오는지 본다. 밝기는 약.25초, 렌즈 여운은2초다. 배경 상하 뒤집힘/이동·원래 밝기 변화/검은 경계/중앙 찢어짐이 없어야 한다. Play 중 Background_Flash Image의 enabled가 꺼져 있어도 같은 원본 이미지를 카메라가 표시하는 것이 의도다.
5. 다음 원형은 두어 변형.15→짧은 반동.05→돌진.20/.60배가 그대로인지, 변형 중 접촉 제거와 돌진 중 접촉/잔상 방어 불가가 유지되는지 확인한다. 넥서스 외곽 피해1회/반복 생성 시 충전 외형 복원도 본다.
6. 타격 직후 일시정지/재개, Retry/Home/재시작을 한 번씩 확인한다. 사용자 pause가 자동 풀리거나 배경이 밝게 남으면 실패다. 기존 육각 충전/반사 파괴와 넥서스 표시가 이전과 같은지도 짧게 확인하고 Play를 종료한다. 이번 자동 실행은 없었으므로 이 결과는 사용자 확인으로 따로 기록한다.

피드백은 **원형 충전 정지 화면 한 장 + 원형 접촉 전후 짧은 영상 + 달라진 개발 수치 보고서 + 새 Console 오류**면 충분하다. 원하는 강도/여운 판단과 기술 오류를 나눠 알려 주면 다음 수정 범위를 원형에 한정할 수 있다.
