## 원인과 수정

### 연결부와 끝

이전에는 반투명 스트립/캡/분기/장식을 화면에 각각 SrcAlpha 합성했다. 같은 면이 겹치면 `a+a(1-a)`로 농도가 커졌고, degree3 이상 분기는 폭이 겹쳤다. 새 방식은 **회로 전용 투명 타깃에 premultiplied RGB/알파의 Max 합집합**을 만든 뒤 게임판에 한 번 합성한다. 두께를 낮춰 접합을 숨기는 조치와 별개다. 내부 조각/분기/캡이 겹쳐도 알파를 더하지 않는다.

기존의 연결 miter/유한 접합 폭은 유지하고 실제 분기는 가장 굵은 연결 선의 반폭 안에서만 둥글게 메운다. 중간 스트립의 양 끝 색을 같은 위치에서 계산하며 진행 끝/자유 끝은 선 반폭의 일관된 캡을 사용한다. 큰 링·중앙 점·보라 받침은 **동적 회로에서 전부 제거**했다. 별도 큰 대체 장식은 없다. 원본 PNG 비교 모드에는 보존한 원본의 원 장식이 그대로 보이는 것이 정상이다. 예전 단자 필드2개는 직렬화/되돌림 호환용으로 숨겨 두고 렌더링하지 않는다.

경로/점/분기 인덱스·배치·밀도는 D-047과 동일하다. 기본10묶음/62선/72점이며, 명시적인 연결 정점만 타격 전파에 사용한다. 그림에서 교차하는 다른 묶음은 연결하지 않는다. CircuitPulseField 기존 알고리즘도 변경하지 않았다.

### 개별 선 흡입

이전 Recall은 모든 점에 중심 기준 회전·비례 축소를 적용하고 선폭도 함께 줄였다. 새 CircuitIntake는 각 연결 묶음의 안쪽 끝을 고르고, 각 점에서 그 끝까지 이어지는 실제 경로의 거리/다음 정점을 미리 계산한다. 끝이 먼저 넥서스를 향한 한 번의 짧은 곡선으로 당겨지고, 뒤쪽 재료점은 기존 연결 경로를 따라 이동한 뒤 같은 곡선을 따라 들어온다. 뒤쪽에는 거리의12%에 해당하는 짧은 당김 지연을 두며 공유 분기점의 위치는 어느 연결 선에서 계산해도 같다. 전체 배치의 아핀 축소/전체 선폭 축소는 제거했다.

기존 Exit.Suction의0~1 진행만 사용한다. **A .20초에는 이동0, B .51초 안에서 묶음별 시작 시차≤진행.12(최대.0612초)/도착 진행.90~1을 배분**하고 기존 C .24초 안정화를 유지한다. 총.95초·실제 피버8초/게이지 소진/공급·점수·링/검정 노드/흑백 공간·광학 시계는 변경하지 않는다. 곡선은 한 번만 휘며 여러 바퀴 회전하지 않는다. 회로 선폭은 유지하고 **실제 점선 링의 기존 RestRadius**에 도착하는 부분부터 클립한다. 흰 영역 마스크만 쓰면 뒤쪽 선이 링에 도착하기 전에 경계에 가려질 수 있었다. 회수 중인 회로만 기존 게임판 레이어(-950)의 컬러 원본에도 같은 좌표/커버리지로 그린다. 흰 세계 쪽에도 같은 회로를 넣어 경계에서 두 표현을 교차 합성한다. `a(1-m)+am=a`이므로 경계가 지나가도 사라지거나 알파가 두 배가 되지 않는다. 컬러 공간의 기존 회로 복원은 그대로 진행하며 합집합 마스크로 중복 농도를 억제한다. 게임 요소/배경 점수보다 위에 새 회로를 덮지 않는다. 흑백 영역·노드·링/색수차의 구현을 새로 만들지 않았다.
