# D-058 — 원호 시간차·피격 되감기·피버 RGB·중앙 점수·회로 반응

상태: **IMPLEMENTED / REFERENCE_COMPILE_PASS / PURE_LOGIC_PASS / UNITY_VISUAL_NOT_RUN / 사용자 검수 대기**. 2026-10-27 사용자 최신 원호/피버/게이지/점수/회로 피드백을 반영했다. 첨부 `codex-clipboard-5ccbf4ed-5f78-4021-98ee-4a6efc328032.png`를 실제로 열어, 바깥 충전 원호가 함께 벌어진 현재 상태를 확인했다. 수정 후 게임 화면 증거로 이 이미지를 사용하지 않는다.

기준 main `18b25da2a2f1d067a028a1ee855c9c8419fd63c4`, 기존 D-055~057 미커밋을 보존했다. 작업 전1546파일 해시/관련 원본 사본은 `Backups/arc-rewind-fever-circuit-20261027`, 검사 결과는 `Cursor-Dash-master/Logs/arc-rewind-fever-circuit-20261027`에 있다. 이번에는 Unity 창 조작·Play·저장/폐기·재임포트·앱 재실행·빌드·커밋·push·배포를 하지 않았다. 현재 메모리 dirty 상태를 새로 읽었다고 주장하지 않는다. D-014 보존 범위는 확대하지 않았다.

## 원인과 수정

### 바깥 충전 원호만 따로 움직임

기존 `NexusMagnetism.Arc`는 모든 원호에 동일한 `charge+.055초` 맥동을 사용했다. 작은 평상시 위상 차이는 있었지만 충전 팽창이 거의 동시에 나타났다. 각 원호의 각도로 정해지는 **고정 위상·작은 강도 차이**를 주었다. 매 프레임 랜덤이나 새 회전 연출을 만들지 않았다. 기본 이동량은 `.8`로 줄여, 같은 위상에 대해 이동 변위가 정확히80%가 된다. 위상별 작은 강도 차이 때문에 이전 동시 팽창 대비 실제 최대 차이는 원호마다 조금 다르다.

`nexusArcMotion=.8`, `nexusArcStagger=.12초`를 기존 VisualPrototype Inspector에 추가했다. 기본 순수 표본에서 원호5개의 팽창 정점은 충전 후 `.284/.230/.314/.208/.324초`로 달랐다. 이 값은 실제 Unity 프레임 실측이 아니다. **승인한 본체 호흡 .04/충전 .24/압축 .32·밝기/점선 링의 반응은 변경하지 않았다.** 실제 충전 비율·원호5개·충전 끝점·피버 진입/종료 움직임도 유지한다.

### 피격 게이지 되감기

기존은 `.16초`의 `(1-t)^3` 감소였다. 0.08초에 이미87.5%가 사라져 역으로 걷히는 모습을 읽기 어려웠다. 피격 프레임 전체의 경과 시간을 새 연출에 바로 적용하는 경로도 있었다.

표시만 `.38초`, `1-SmoothStep(t)`로 바꾸고 **첫 렌더에서는 피격 직전의 표시량을 유지**한다. 새 곡선은 .095초에84.375%, .19초에50%가 남고 .38초에 정확히 현재 실값으로 수렴한다. 실제 모델은 피해 순간 즉시0/배율1이다. 표시 원호의 Head가 기존 시계방향 충전 경로를 역으로 되짚는다. 되감기 동안 매 tick 최신 실제 충전 목표를 읽고, 재피격은 현재 표시에서 재시작한다. 오래된 완료 콜백이 새 충전을 덮는 방식은 사용하지 않았다. Pause에서 표시 시계는 정지하며 피버의 정상 소진/종료는 변경하지 않는다.

### 피버 색수차와 점수

기존 `FeverWorldTransition.FinishBoard → FeverImpact`는 넥서스·커서 합성까지 완료한 게임판을 읽는다. 이 소스에는 배경 점수도 포함된다. `_DamageTextMask`는 일반 피해 블록에서만 쓰이며, 피버 RGB에는 원래 점수 제외 처리가 없었다. 이 경로를 재사용하고 피버 타격 RGB `.0042→.006`, 유지 RGB `.0008→.0012`, 두 값의 최종 피버 합성 상한 `.006→.008`로 보완했다. 숫자의 위치/형태를 복제하거나 별도의 숫자를 만들지 않았다.

일반 피해의 점수 획 보호와 `.018` RGB/국소 붉은 굴절, 승인된 피버 종료의 RGB `.006` 상한·노드/공간/링 회수는 보존했다. 후단의 고정 HUD/메뉴는 계속 별도 표시한다. 효과 OFF/사용자 distortion 강도도 존중한다. 실제 GPU에서 점수의 RGB 가장자리가 어떻게 읽히는지는 사용자 검수 대상이다.

### 배경 점수 중앙 고정

실제 저장된 `backgroundScoreY`와 소스 fallback이 `.58`이었다. 이를 모두 `.5`로 바꿨다. X=.5, Rect4×4, Scale1, AutoSize1~3.5, 실제 글자 bounds를 중심에 맞추는 기존 정점 보정은 유지한다. 득점 탄성은 중심을 기준으로 크기만 바뀐다. 같은 점수 하나의 메인↔인게임 크기·색·숫자 변화는 유지하되 목표 위치가 이제 화면 중앙이다. 최고점/현재 점수 데이터와 저장 경로는 수정하지 않았다.

### 처치 회로 강조와 넥서스 피해의 붉은 전파

처치의 기존 연결 경로/분기 전달은 그대로 사용한다. 대비를 기본 화면 전체에 올리는 대신 타격 강조량 `.18→.32`, 펄스 길이 `.24→.34초`, 거리 감쇠 길이 `.26→.40`, 가까운 회로를 찾는 범위 `.13→.18`로 보완했다. 전달속도1.65/반응 동시 상한4/평상시 흐름·회로 폭·배치·기본 색·대비는 유지한다. 비교 값의 거리는 화면 짧은 변에 대응하는 기존 회로 좌표 단위다.

실제 비치명 HP 감소의 기존 `OnNexusHealthLost → Fever.NexusVisualHit`에 `Circuits.NexusDamaged()`를 연결했다. 실제 넥서스 월드 위치를 회로 좌표로 옮겨 **단일한 방사형 강조 전면**이 기존 회로 선을 차례로 붉게 만든다. 성공 타격이 그래프를 따라 전달되는 것과 별개인 공간 반응이다. 새로운 선이나 연결 관계를 만들지 않는다. 반사/점수만의 사건·무효 피해·무피해 훈련 접촉은 붉은 파동을 만들지 않는다.

붉은색은 기존 `nexusDamageTint`를 사용한다. 강조 .44/속도2.6/전면 뒤 폭.26/최대.80초. 매 피해마다 하나의 상태만 갱신하며 무한 합산하지 않는다. 실제 Pause에서는 멈추고 Home/Retry/상태 전환/사망/비활성화에서는 정리한다. 사망은 기존 회로 바깥 퇴장·최종 파괴를 우선한다. 기존 `DrawLayer`의 보이는 길이와 같은 숫자 획 마스크를 사용하므로 이미 걷힌 구간이나 숫자 획 위에 강조만 별도로 그리는 경로를 추가하지 않았다. OnFlash·user.flash·fx.enabled를 존중한다. 매 피해마다 메시·재질·오브젝트를 새로 만들지 않는다.

## 사용자 수동 검수 순서

1. `Assets/Scenes/Cyberpunk.unity`를 사용한다. 메인→시작→인게임에서 같은 배경 숫자의 보이는 중심이 화면 중앙인지, 한 자리/여러 자리/득점 팝 후에도 Y로 이동하지 않는지 확인한다.
2. 일반 노드를 여러 번 처치한다. 승인한 본체 반응은 유지되며 바깥 충전 원호는 서로 조금 다른 시점에 벌어지고 이동량은 줄어야 한다. 처치 근처 회로의 청록 강조가 기본/평상시 흐름보다 선명한지 확인한다.
3. 충전 25%/50%/75% 이상에서 비치명 피격. 실제 충전/배율은 즉시0/1, 원호 표시만 역방향으로 .38초 동안 걷혀야 한다. 동시에 실제 중앙에서 붉은 강조가 회로를 바깥쪽으로 지나가는지, 점수 글자 획은 계속 회로를 가리는지 확인한다.
4. 되감기 중 재충전·추가 피격을 비교한다. 표시가 과거 값으로 되살아나거나 새 충전을 덮지 않아야 한다. 별도 훈련 라운드의 기존 `Tools → CursorDash → 넥서스 수동 검수`를 활용할 수 있으며 기록 검수와 구분한다.
5. 피버 중 가만히 있을 때/연속 처치에서 검은 도형·점수 글자의 RGB 가장자리를 비교한다. 버튼·HUD는 읽혀야 하고 일반 모드 복귀 뒤 피버 RGB가 남지 않아야 한다. 효과 강도 감소/OFF도 비교한다.
6. Pause·재개, Retry, Home, 피버 종료, 체력0 뒤 복귀를 확인한다. 회로 파동/역감소/원호 기준·중앙 점수/색수차가 남거나 이중 실행되지 않아야 한다. 실제 화면 비율·모바일의 가독성은 별도 검수다.
