# D-035 — 육각 회전 차징과 피버 광학 소폭 강화

날짜: 2026-10-26. 출처: 최신 사용자 요청. 상태: **소스 수정·정적/순수 검사 완료, 사용자 Unity·GPU 검수 대기**.

## 육각 동작

기존 프리팹 `Assets/Prefabs/Nodes/Cyberpunk/ArrowNode.prefab`의 두 테두리는 각60도 이동.4초→정지.4초, 방향만 반대다. 이번에 말하는1회는 이 눈에 보이는 이동 동작이며360도 전체 회전이 아니다. 두 링을 합쳐 두 번으로 세지 않고 `Outside 1`의 실제 소유 tween 진행을 읽는다. 별도 타이머가 회전과 비슷하게 맞춰지는 방식은 사용하지 않는다.

| 기존 테두리 동작 | 충전 | 생성 후 기본 시각 |
|---|---|---|
| 1회째 이동 | 0→1/3 | .4초 완료 |
| 2회째 유지, 3회째 이동 | 1/3→2/3 | 2.0초 완료 |
| 4회째 유지, 5회째 이동 | 2/3→완충 | 3.6초 완료 |
| 6·7회째 | 완충 유지 | 5.2초에 기존 변형 시작 |

충전 완료마다 기존.14초 짧은 탄성/밝기 반응을 유지한다. 마지막은 짧게 눌린 뒤 완충으로 안정한다. 기존 이동속도·정지 간격은 바꾸지 않았다. 따라서 **이전 준비3.5초→현재5.2초(+1.7초)**다. 최신 동기화 요청이 D-034의 준비시간 고정을 대체한 결과이며 다른 전투 수치를 함께 변경한 것이 아니다.

변형.25초→예비.025초→레이저 비행.06초는 유지했다. 명목상 발사3.775→5.475초, 도달3.835→5.535초다. 실제 프레임 측정 결과가 아니며 한 프레임 단위 차이가 생길 수 있다. 완충 이후 테두리2회에 해당하는 명목 대기는1.6초다. 변형·주 발사 반동/뒤→앞 에너지 배출·전체 경로 잔상 방어/반환·피해는 기존 코드를 보존했다.

회전속도 배율을 바꾸면 다음 생성부터 차징도 함께 바뀐다. 정지.4초는 기존대로 유지되어 준비길이는 `7 × (.4 / 회전배율) + 6 × .4`초다. 예: 배율.5→8.0초,1→5.2초,2→3.8초,4→3.1초. 프리팹 Rotator의 duration/interval을 바꾼 경우에는 그 실제 값으로 계산한다. 프리팹 자체는 이번에 저장하지 않았다.

첫 링이 사용 불가능하면 둘째 링을 읽는다. 두 링 모두 끄거나 회전배율0이면 기존 `hex.prepare`(기본3.5초) 안에 가상7단계를 배분해 교착을 피한다. 이 경우 검수창은 ‘회전 없음 — 준비시간 안전 대체’로 구분한다. 일반적인 회전ON 동작을 승인한 것으로 fallback 동작까지 확정하지 않는다.

`Rotator` 공유 컴포넌트의 원래 회전 Sequence/무한반복/각도/방향/선형 Ease/정지 코드는 그대로다. 실제 경과와 실행 시간 값을 읽는 기능만 추가하고, 육각 Execute에서 자기 두 링만 재시작한다. 원형/HP 회전은 같은 스케줄을 유지한다. LateUpdate에서 게임진행·일시정지 가드 뒤에 진행을 읽고, 취소/풀복귀/새 실행에서 진행·반응 시각을0으로 복원한다. 예약 콜백으로 공격을 발사하지 않는다.

## 피버 광학

기존 Built-in 최종게임판 패스(넥서스→흰세계/노드/파편→실제커서→광학, 그 뒤 고정HUD)를 그대로 사용한다. 새 파편/플래시/쉐이크 패스를 덧쌓지 않았다.

| 조절 항목 | 이전 | 이번 초기값 | 영향 |
|---|---|---|---|
| Fever Lens Strength | .014 | .0175 | 렌즈 굴절과 국소 수평슬립 +25% |
| Fever Chromatic Hit | .0035 | .0042 | 타격 RGB 분리 +20% |
| Fever Chromatic Ambient | .00065 | .0008 | 피버 유지 RGB 분리 약+23% |

시간.30초/범위.58/최강 필드 선택/최대 변위.018·RGB.006 상한은 그대로다. 위 값은 화면축 UV 계수이며 모든 픽셀이 같은 양으로 움직인다는 뜻이 아니다. 타격이 겹쳐도 강도를 합산하지 않는다. 흰 배경·검정 내부는 유지하고 경계에서 색이 분리된다. 쉐이크.45배/파편강도2.5·수명.48/히트스톱 상한·간격은 유지했다. 일반모드 화면효과·노드파괴/넥서스 최종파괴도 변경하지 않았다.

사용자 왜곡0/FX OFF/접촉위치진단ON이면 기존 정책대로 광학을 우회한다. 현재 사용자 설정은 초기화하거나 덮어쓰지 않았다. 실제 Inspector/Prefs 런타임 값을 읽은 것이 아니라 코드·asset 기본값이다.

## 조절 위치

- 개발자 수치 도구의 **육각 회전·차징 속도**(`hex.spin`): 다음 생성부터 실제 회전과 차징 속도. 정지 간격은 유지된다.
- 육각 프리팹 `Node/Outside 1`, `Node/Outside 2`의 Rotator: Angle60, Duration.4, Interval.4. 첫 링 기준이며 양쪽 속도를 다르게 설정하면 첫 링을 따른다.
- ArrowNode의 **Charge Beat Settle Seconds=.14 / Elasticity=.06**: 완료 시 짧은 탄성만. 옛 Rise=.18/Hold=.95 저장값은 숨겨 보존했으며 이번 차징에 사용하지 않는다.
- `hex.prepare`는 **육각 회전 꺼짐·누락 시 준비**로 설명을 바꿨다. 키/기본값/프리셋 스키마는 바꾸지 않았다. 회전ON에서는 준비길이를 제어하지 않는다.
- `Assets/Resources/CursorDash/VisualPrototype.asset`의 **Fever Lens Strength / Chromatic Hit / Chromatic Ambient**: 위3값. 프로필/없을 때 fallback도 같은 값이다.

## 사용자 Unity 검수 순서

1. `Assets/Scenes/01.StageSelectScene.unity`를 열고 직접 Play→훈련. 기존 `Tools/CursorDash/넥서스 수동 검수`에서 **B/D 육각1개 생성**. 기본 회전배율1에서 테두리1·3·5회에1/3·2/3·완충,6·7회는완충을유지한뒤변형·발사되는지 본다. 검수창의 ‘육각 차징 기준/회전·충전단계’가 실제 첫테두리/7과3단계로 표시된다. 외형과 링 두께/노랑은 그대로여야 한다.
2. 필요하면 기존 수치 도구의 회전·차징 속도만 바꾸고 **새 육각**을 생성한다. 속도가 바뀌어도 같은1/3/5·7회 관계인지 확인한다. 사용자가 저장한 프리셋을 초기화하지 않고 현재값과 함께 비교한다. 검수 뒤 원래값으로 조절한다.
3. 준비/완충 중 일시정지→재개. 회전/충전이 같이 멈췄다 이어지는지, 풀 재사용 때0부터 시작하는지 본다. 피버 진입/Retry/Home로 취소하면 이전 레이저가 뒤늦게 나오면 안 된다. 잔상으로 빠른 레이저를 반환해 기존 육각 파괴가 유지되는지도 확인한다.
4. 훈련에서 자연 피버 또는 기존 수동 검수 버튼으로 피버 진입. **FX ON, 사용자 왜곡1, 접촉위치진단OFF**에서 검정 원을 단발/연속 타격한다. 렌즈의 휘어짐/수평으로 짧게 밀리는 부분/도형 경계RGB가 조금 더 강하게 읽히고, 상단 점수·배율·일시정지 UI는 흔들리거나 색분리되지 않아야 한다.
5. 잠시 멈추고 종료/취소·일시정지·Retry/Home/체력0을 확인한다. 왜곡은 추가 누적 없이 감쇠하고 일반모드에는 RGB가 남지 않아야 한다. 검정 원의 마지막.55초 축소/2.8초수명·공급과 입력/파편강도는 이전과 같다. 실제 광학 호출 카운터가 늘어도 화질·위치 정합을 함께 눈으로 확인한다.
