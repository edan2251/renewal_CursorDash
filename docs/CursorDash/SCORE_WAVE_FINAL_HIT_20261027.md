## 1. 처치 회로 빛: 실제 타격점에서 독립 경로까지

기존 처치는 타격점에서 가장 가까운 회로를 찾아 연결된 그래프 안에서만 반응을 전달했다. 다른 독립 회로로는 전달되지 않았고, 근처 회로가 탐색 범위 밖이면 시작되지 않았다. 이번 요청의 ‘타격점을 중심으로 전체 회로’에 맞춰 **처치만 공간을 가로질러 퍼지는 전면**으로 바꿨다.

실제 `HitFeedback`의 `circleRemove/triangleBreak` 타격점 → `Circuits.ScoreHit` → 기존 `CircuitPulseField.HitRadial` 풀을 사용한다. 피버 보너스 처치도 기존 `BonusFeel`에서 같은 ScoreHit로 연결한다. 오래된 꼬리나 현재 커서 위치를 새 원점으로 쓰지 않는다. 반사 방어와 무피해 접촉은 기존 국소 연결 경로를 유지한다.

전면 속도2.6/폭.32(기존 짧은 화면 변 기준 회로 좌표), 강조 상한 .32→.44. 마지막 경로까지의 거리와 폭으로 수명을 계산해 화면 크기에 맞춰 도달한 뒤 정리한다. 기존8슬롯 풀/설정 동시상한4를 재사용하고, 연속 처치가 무한히 쌓이지 않게 가장 오래된 반응을 대체한다. 새 메시/재질/관리자를 만들지 않는다. 그래프 모양·실제 연결 관계·평상시 흐름은 변경하지 않았다.

기존 보이는 길이를 먼저 자르는 `DrawLayer`와 숫자 실제 획 마스크를 그대로 통과한다. 피버에서 이미 걷힌 구간이나 점수 획 위에 빛만 별도로 만드는 방식이 아니다. Pause/전환/Retry/Home/사망의 기존 정리 경로를 사용한다.

### 피격 우선순위 확인

기존에는 강조량을 `Max`로 고르고 색을 붉은색 쪽으로 혼합했다. 강한 처치 강조가 붉은 피격 구간에 섞이는 것을 완전히 막지는 못했다. 별도 우선순위 관리자를 추가하지 않고 **기존 Tint 함수 안에서** 붉은 피격 전면의 강도에 따라 처치/평상시 강조를 억제한다. 붉은 전면이 가시 강도 .08 이상이면 해당 구간은 붉은색과 피격 강조만 사용한다. 시작/감쇠 구간은 부드럽게 넘겨 갑자기 색이 끊기지 않게 한다. 서로 겹치지 않는 곳의 처치 빛은 계속 진행한다.

## 2. 피버 점수의 더 강한 색수차

기존 게임판 RGB 타격 `.006→.008`, 유지 `.0012→.0018`, 기본 피버 합성 상한 `.008→.012`. 추가로 **점수 획 안의 RGB 배율3**/상한.024를 적용한다. 배경 점수는 반투명한 기존 색·크기 그대로이며 채널을 서로 다른 위치에서 읽어 색 가장자리를 만든다. 글자를 불투명하게 하거나 새 숫자를 겹치지 않는다.

실제 TMP 메시·현재 정점 변환에서 만드는 기존 점수 획 마스크를 재사용한다. 회로 가림 비교 토글을 꺼도 피버 점수 RGB에 필요한 마스크는 만들 수 있게 했으며, 그 경우 회로 가림 `_ScoreHide`는 계속0이다. 서로 다른 기능의 토글을 잘못 결합하지 않는다. 일반 피해의 글자 보호·일반 모드·안정 HUD·피버 종료의 기존 색수차/흡입은 유지한다. 사용자 효과 강도0이면 점수 RGB 증폭도0이다.

## 3. 이번 점수 표시의 호흡

현재 공유 Cyberpunk 흐름은 별도 ROUND OVER 팝업 대신, 이번 점수가 메인 위치로 돌아와 새 클릭을 기다리는 Returning 상태다. 이 표시를 대상으로 했다. 회로 재구축/점수 이동·색 변화가 끝난 뒤 **±2.5%/2.4초** 주기의 작고 부드러운 크기 호흡을 시작한다. 진입 초반에는 호흡을 넣지 않는다.

새 클릭 후 BEST로 바뀌는 기존 .45초 구간에서 호흡을1로 감쇠시키고 메인/다음 시작에는 남기지 않는다. 현재점수/최고점/표시숫자를 추가로 바꾸거나 기록 이벤트를 만들지 않는다. 기존 TMP 정점 변형으로 처리해 Transform Scale1/Rect4×4/AutoSize1~3.5·화면 중앙을 유지하며 회로 획 가림도 같은 프레임의 실제 글자 모양을 따른다.

## 4. 마지막 피격의 옛 화면 효과 제거

확인된 기존 경로: 첫 두 비치명 피해는 `ConfirmedNexusDamage → DamageSignal(true,contact)`였지만, 치명 피해는 `EmitFinalCommitted → DamageSignal(false)`였다. 치명타만 전체 붉은 flash .26/.24초·약한 RGB.0055·waveOFF와 별도의 옛 distortion을 사용했다. 사용자 관찰과 일치하는 코드 차이다.

확정 치명 피해도 **같은 DamageSignal(contact)**을 사용한다. 설정은 현재 일반 피격과 동일한 .48초/색수차.018/공간 파동/전체wash0이다. 실제 마지막 접촉점을 보존한다. 흔들림도 일반 피해와 같은 nexusDamage 설정/길이를 사용한다. 일반 피해와 치명 피해 화면 효과를 두 번 겹치지 않고 이전 치명 전용 전체 플래시·중복 왜곡을 제거했다.

최종 파괴 이벤트 뒤에도 실제 중앙의 붉은 회로 전파를 시작할 수 있게 하되, 회로의 기존 바깥 퇴장을 그대로 따른다. 도달하지 않았거나 이미 걷힌 부분을 다시 그리지 않는다. 최종 파괴 파편·공격 방향·슬로모션·정산·메인 복귀 시간은 **그대로**다. HP0 처리/정산/저장은 추가 호출하지 않는다. 실제 피해가 아닌 수동 강제 Death의 흰 피드백은 확정 피해와 구분한다.

## 사용자 확인 순서

1. `Assets/Scenes/Cyberpunk.unity`에서 일반 노드를 중앙/좌우/상하에서 파괴한다. 실제 타격점에서 전면이 퍼져 다른 독립 회로에도 도달하는지, 평상시 회로는 그대로인지 확인한다.
2. 처치 직후 넥서스에 피해를 받아 두 전면을 겹쳐 본다. 겹친 곳은 붉은 피격 빛이 우선하고 다른 곳의 처치 빛은 이어져야 한다. 숫자 획/걷힌 경계에서 빛이 새로 그려지지 않아야 한다.
3. 피버 대기/연속 처치에서 배경 점수의 RGB 가장자리를 비교한다. `feverScoreChromatic=1/3` 비교, 사용자 효과 강도 감소/OFF, 회로 가림 토글 OFF도 확인한다. 고정 HUD는 계속 읽혀야 한다.
4. 같은 라운드에서 HP3→2→1→0을 비교한다. 마지막 공격도 같은 붉은 굴절·색수차·흔들림이어야 하고 옛 전체 붉은 flash가 다시 나오면 안 된다. 최종 파편/슬로모션·이번점수 복귀는 유지되어야 한다.
5. 이번점수가 자리를 잡고 클릭 대기할 때 작은 호흡을 관찰한다. 숫자/기록/중심은 유지되고 새 클릭→BEST→다음 시작에는 호흡이 남지 않아야 한다. 작은/여러자리 점수에서 확인한다.
6. Pause·재개/Retry/Home/피버 종료·사망을 반복하고 효과와 시간이 남지 않는지 확인한다. 훈련·검수 조작은 기록 검수와 구분한다.
