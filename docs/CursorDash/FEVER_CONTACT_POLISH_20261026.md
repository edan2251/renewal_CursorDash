## 판정과 파괴가 약해 보이는 경로를 먼저 수정

1. **물리 루트의 플래그**: 보너스 풀/Collider 루트가 DontSave였다. Unity 공식 문서는 이 플래그에 포함되는 DontSaveInEditor/Build가 객체를 물리 장면에서 제외한다고 설명한다. 실제 현재 Editor에서의 참여 상태는 관측하지 않았으나, 그 위험이 있는 설정은 확정해 제거했다. 풀·충돌 루트는 일반 런타임 객체, Mesh/Material/표시 전용 자식만 DontSave다. Play에서 생성하고 소유 Stage가 파괴하며 씬을 저장하지 않는다. [Unity HideFlags](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/HideFlags.html)
2. **보이는데 먼저 꺼지는 판정**: 기존 Advance는 수명 마지막 .14초에 도형이 보이는 동안 collider를 끄고 있었다. 수명2.8초/페이드 길이는 그대로 두고 실제 제거 때까지 수집 가능하게 했다. 기존 비수집 꼬리5%를 시각과 일치시키는 버그 수정이며 생성량/주기를 늘린 것이 아니다.
3. **프레임 사이 이동**: 기존 Trigger Enter/Stay에 더해 커서의 이미 예약된 FixedUpdate 이동 시작→끝을 같은 실제 BoxCollider 크기/offset/회전으로 검사한다. 직사각형을 무작정 팽창한 AABB가 아니라 네 모서리가 둥근 box-circle 연속 교차다. 같은 프레임의 정지 겹침도 검사한다. 일반 노드·입력·잔상 방어는 기존 경로다. 회전하는 박스의 스텝 사이 자세는 해당 물리 스텝의 현재 자세를 사용하며 실제 Physics/보간은 사용자 검수 필요다.
4. **중복 방지**: Sweep/Enter/Stay 모두 FeverBonusNode.TryCollect에서 removed를 먼저 점유한다. 이후 기존 실행 ID의 Model.Kill이 점수1회→전용 파괴1회→풀 반환을 처리한다. 만료/정리에는 점수/VFX를 주지 않는다. 늦은 콜백/같은 실행 재수집은 거부한다.
5. **파편이 흰 패스에서 지워지는 경로**: 파편은 DontSave인데 이전 마스크 수집은 FindObjectsByType였다. 공식 API가 제외하는 대상이므로 생성 성공과 화면 합성 성공이 분리돼 있었다. 필드가 이미 소유하는 bursts 목록/실제 MeshRenderer를 직접 전달한다. 매 프레임 장면 전역 검색도 제거했다. 이 연결 수정의 최종 GPU 결과는 미검수다. [Unity FindObjectsByType](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Object.FindObjectsByType.html)

보너스의 도형은 단위 반경1, collider.radius=1, 표시/위치 이동은 같은 루트다. 원래 .205×변형(.85~1.12), 첫 .10초 .70→1 크기·작은 이동은 유지했다. 충돌체를 별도로 키워 덮지 않았다. 평상시 원형의 기존 완성 접촉 반경.62는 보존하고 등장 동안 같은 비율로만 축소한다. 승인된 기본 외형에 대한 기존 접촉 여유까지 새로 조정하지 않는다.

## 사용자 Play 검수 순서

메인 **Assets/Scenes/01.StageSelectScene.unity**에서 직접 Play→훈련, 게임 씬은 **Assets/Scenes/Cyberpunk.unity**다. Console의 새 오류부터 확인한다. 기존 설정에서 효과/파편을 껐다면 의도적으로 생성하지 않으므로 검수할 때 해당 상태도 확인한다. 자동으로 사용자 설정을 초기화하지 않았다. 훈련/개발 조작은 최고점수 기록에서 제외된다. 설정을 초기화하거나 저장 데이터를 삭제하지 않는다.

1. **일반 등장**: 기존 생성 버튼/훈련으로 원형·육각을 여러 번 만든다. .20초 안에서 본체 쏙→같은 회전 방향의 테두리 후행→한 번의 미세 초과/안착을 본다. 원형 위에 커서를 미리 놓았을 때 보이지 않는 순간에 파괴되지 않고 나타난 크기와 맞게 닿는지도 확인한다. 등장 중 제거·풀 재사용 뒤 되살아나는 연출이 없어야 한다. 원형 돌진과 육각 레이저/반사는 기존 리듬이어야 한다.
2. **충전**: 처음0%에는 바깥선/시작선/중앙 글자가 없어야 한다. 실제 처치8회 기본값으로5호 안에서도 연속 충전되며 짧게 밝아지는지 본다. 점선만 느리게 돌고 이벤트 후 안정되어야 한다. 평상시 배경은10~20초 동안 넓은 색 경계가 실제로 흐르는지 본다.
3. **흡수·전체 화면**: Tools→CursorDash→넥서스 수동 검수에서 낮은HP15% 후 만충을 써 빠르게 비교할 수 있다(내부 모델 조작이며 실제 처치가 아님). 바깥 선행→점선 후행, 본체 안쪽 잔선0, 응축/빠른 흰 확산을 본다.9:16/더 긴 세로/16:9에서 모서리까지 흰 배경, 점수/일시정지의 가독성과 잘림 없음. 본체/실제 경계는 기존 위치다.
4. **피버 충돌·파괴·궤적**: 그룹을 향해 실제로 이동한다. 정면/대각선/빠른 통과·페이드 중 직접 충돌을 각각 확인한다. 하나당 현재배율 점수1회/노드 제거1회/검은 파편1회여야 한다. 수동 검수창의 수집/연속 경로 숫자는 진단일 뿐 Play 성공을 대신하지 않는다. 연속 그룹을 지나도 조작이 장시간 멎거나 파편이 규칙적 점 고리만 되면 실패다. 검은 궤적/커서가 파편과 구분되어야 한다.
5. **종료·배율**: 검은 호가 순차 소모되어 사라지고 점선은 유지 중 숨김, 종료에 곡선 에너지가 바깥→중심으로 이동하며 링/현재 색 흐름이 복원되어야 한다. 점수 옆 ×2가 한 번만 펄스하고 중앙/하단은 비어야 한다. 반복해서 ×3→×4→×4 유지, 피격 시 ×1 숨김/게이지0·점수 보존을 본다. 최고점수/이번점수는 기존 분리 유지다.
6. **일시정지·Retry·Home**: 등장/흡수/피버/종료 중 각각 다른 회차에 pause/resume·Retry·Home을 해 본다. 타이머/파편/배경/링이 중단 상태를 지키고 새 회차에 잔여 연출/옛 색 궤적/예약 공격/배율 중복 상승이 없어야 한다. Pause/설정 UI는 커서 위, 커서는 넥서스 위여야 한다. HP0과 결과/재시도도 확인한다. 기존 일반 파괴·레일건 방어·최종 파괴는 새 배경에서 깨지지 않았는지만 비교한다.
