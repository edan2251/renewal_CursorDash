# D-069 — 정지 후 남은 꼬리의 방어 연결 (2026-10-29)

## 요청과 원인

사용자는 ‘정지시에 남아있는 꼬리도 육각노드의 공격을 막을 수 있게’라고 명확히 했다. D-067/068에서 이를 표시만 남기는 것으로 해석한 부분을 바로잡는다. 기존 미커밋 표시 복구·고스트 감속·문구·점수 전환은 보존한다.

실제 육각 `ArrowNode.Update`는 발사 중 소속 `PlayerCharacterAfterImage.TryBlockBeam(origin,tip,...)`을 호출하고, 이 함수는 수명 내 이동 샘플만 검사했다. 따라서 LineRenderer에 남은20% 꼬리와 실제 방어 경로가 달랐다. 육각은 AfterImage의 BoxCollider Trigger로 반사하는 구조가 아니다.

## 수정

- 기존 `TryBlockBeam`에서 **표시에 쓰는 동일한 머리→꼬리 폴리라인**을 검사한다. 별도 방어 경로나 관리자를 만들지 않는다.
- 조회 때 현재 머리와 게임시계로 같은 표시 경로를 갱신하므로, 육각 Update가 꼬리 LateUpdate보다 먼저여도 오래된 머리를 검사하지 않는다. 정점 변화가 없으면 렌더러를 다시 쓰지 않는다.
- 실제 플레이어의 정지20%(기본 **.78world**)와 고스트50%(**1.95world**)가 남아 있는 동안 방어 가능하다. 고스트도 동일한 소유권 분리·기존 반환 반사를 사용한다.
- 화면에서 잘려 사라진 옛 이력은 검사하지 않는다. 이동 후 꼬리 경로가 바뀌면 이전 위치는 방어하지 않는다. Clear/비활성화는 이력·표시·잔존 방어를 함께 지운다.
- 기존 판정폭 `trail.hitWidth`와 광선 폭 합산, 광선의 최초 접촉 선택, Block→Resolving/반환·중복 방지·점수 집계는 유지한다. `ArrowNode.cs`는 수정하지 않았다.
- 기존 시간제 Collider 풀은 유지한다. `ActiveSegmentCount`는 그 시간제 샘플의 진단값이며, 0이어도 남아 표시되는 경로는 광선을 막을 수 있다. 잔존 방어를 위해 Collider·재질·오브젝트를 추가 생성하지 않는다.

별도 새 조절값은 없다. 기존 VisualPrototype의 `cursorRestTailFraction=.20`, `tutorialGhostTailFraction=.50`, 고스트 입력 `.375`와 기존 `trail.lifetime=.6782609`, `trail.hitWidth=.0675`를 유지한다. 이동 중 수명에 맞춰 표시되는 긴 꼬리도 같은 표시 경로로 검사한다. 실제 플레이어 속도·입력·회전과 육각 충전·발사·반사 설정은 바꾸지 않았다.

1. **Cyberpunk**에서 육각→넥서스 레이저 길을 가로질러 이동한 뒤 정지한다. 남은 꼬리가 광선 길과 교차하도록 두고 기존.678초보다 길게 기다려도 반사되는지 확인한다. 커서 머리로 육각 본체를 직접 건드리는 검사가 아니다.

4. Pause/재개, Retry/Home 뒤 옛 꼬리·보이지 않는 방어 경로·중복 반사가 남지 않는지 본다. 일반↔피버 꼬리 색 복귀도 확인한다.
