# 옅은 육각 테두리·넥서스 게임판 연결과 즉시 HP 절삭 — D-023

2026-10-25. **구현·정적 확인 완료 / 사용자 Unity 검수 대기.** 원형·육각의 현재 형태와 동작은 사용자 승인으로 보존했다. 공통 타격감은 **최종 미승인**이며 이번 원형/육각 파괴 효과의 수치 튜닝·확장은 하지 않았다. 자동 Play/공식 테스트 실행/Unity·WebGL 빌드/커밋/푸시/배포는 없다.

## 육각 테두리

첫째 테두리는 기존 노란색을 유지하고 둘째만 같은 기본색에 **흰색18%**를 섞었다. 이전 둘째의 어두운.82배 명도를 대체한다. 기본색#FFD466 기준으로 약#FFDC82인 조금 밝고 연한 노랑이다(실제 Inspector/Dev 기본색을 기준으로 계산). 새로운 속성 색을 추가한 것이 아니다.

`HexagonalNodeRings.Draw`의 색 계산만 바꿨다. 승인된 윤곽 데이터/원호 조각·두께/좌표·회전축/속도·충전/6꼭짓점 변형/에너지 배출/발사 코드는 그대로다. 원형 전용 파일은 바꾸지 않았다. 기존 사용자 Dev 색이나 저장 프리셋도 덮어쓰지 않았다.

## 넥서스와 HUD의 연결

기존 `UI/HpBar`(수위), `UI/HpFrame`(회전 장식), `UI/HpCentral`(본체) **3이미지**의 스프라이트·색·현재 회전·사각 영역·그리는 순서를 그대로 읽는다. 원본 이미지의 부모/RectTransform을 이동하거나 씬에 저장하지 않았다.

표시 순서는 기존 게임판 화면 효과 → 기존 Background_Flash → **같은 게임판 효과를 적용한 넥서스** → 기존 고정 HUD다. 배경이 새 넥서스를 덮지 않으며, 본체/수위/장식 모두 실제 월드 카메라의 흔들림과 동일한 왜곡·노출 식에 반응한다. 점수·시간·체력 숫자·버튼·설정·결과창과 기존 입력 경로는 고정 UI에 남는다.

기존 `LocalImpact`의 변위/노출 계산식을 `WorldImpact.cginc`로 **그대로 추출**해 공유했다. 기존 원형/육각 파괴 효과의 계산식과 기본값은 정적 대조로 동일함을 확인했다. 배경 플래시 코드/공통 피격 강도·시간·카메라 셰이크 값도 바꾸지 않았다. 이는 넥서스의 렌더 연결이며 공통 타격감이 완성/승인됐다는 뜻이 아니다.

원래3이미지는 Play 중 중복 렌더링을 막으려고 Image.enabled만 임시 끈다. 재질/스프라이트 자산을 변경하지 않고, 렌더 소유 컴포넌트 비활성화/파괴 때 이전 enabled를 복원한다. 원본과 다른 머티리얼/패킹 등 지원하지 않는 구성이면 원래 UI 표시를 유지한다. 현재 씬의 저장 구성은 지원 범위다. **실제 GPU 성공 여부는 사용자 Unity 검수 대상**이다.

## 위치·크기와 공격 경계

기존 `StageManager`의 첫 레이아웃 이후 확정한 중심/반경을 그대로 사용한다. HP/피해/원형 앞점 판정·육각 빔 경계·게임오버 로직을 바꾸지 않았다. 수위가 줄어도 피격 원의 크기는 줄지 않는다.

현재 원본 HpBar는211×211이고 본체 분율은 **125/211**이다. 표시 좌표는 원본 사각형을 읽고 기존 `NexusPosition`/`NexusRadius`에 정렬한다. 초기 배치·크기는 같고 Game View 화면비 변경으로 CanvasScaler가 재배치돼도 **표시만 안정된 실제 공격 경계에 맞춘다**. 공격 경계를 새로 움직이거나 크게 만들지 않는다. 회전 장식도 같은 비율/중심 보정을 받아 본체와 분리되지 않는다.

UI Canvas 저장값은1080×1920/가로 일치/비PixelPerfect이며 HpFrame277×282,HpCentral169×169다. 직교 카메라 높이10·1080×1920 예시에서 본체 반경은 .3255208월드다. 이는 정적 산출 예이고 모든 Game View에 고정된 반경이라는 뜻은 아니다. 실제 값과 표시-판정의 중심/반경 오차는 수동 검수창에서 확인한다. 기존 디버그 경계선도 게임판 카메라 레이어로 연결해 같은 흔들림/왜곡을 받는다.

## 체력 표시

- **평상시:** 자동 사인파/물결 시계/느린 SmoothDamp를 제거했다. 표면은 수평으로 정지한다. 기존 원본 회전 장식은 그대로 돈다.
- **피해:** 실제 남은 HP 비율을 표시 수위에 **즉시 반영**한다. 0.25초 동안 천천히 배수하지 않는다.
- **감소 순간:** 표면에 작은 아래 눌림을 한 번 주고 **.12실시간 초** 안에 단조롭게 사라지게 한다. 기본.015로컬/상한.025이며 여러 번 튕기거나 계속 파동을 만들지 않는다.
- **연속 피해:** 현재 HP/단발 시작시간으로 교체한다. 트윈/코루틴/연출 큐를 쌓지 않으며 이전 높은 HP로 되감지 않는다.
- **회복·0·pause·비활성화:** 남은 눌림을 지운다. HP0은 같은 프레임에 빈 수위이고 기존 사망 경로가 실행된다. 재시도는 새 실제HP로 시작한다.

기존 `nexus.waveAmplitude` 키를 피격 순간 눌림에 재사용했다. `nexus.smooth`/`nexus.waveSpeed`는 이전 JSON 호환 키로 남기되 미사용을 표시한다. 값/저장 프리셋을 삭제하거나161키 계약을 바꾸지 않았다. 최대HP·피해량·판정·기록·사망 규칙은 그대로다. 새 보호막/장식/통합 수치 패널은 없다.

## Unity 검수 절차

**씬:** 평소처럼 `Assets/Scenes/01.StageSelectScene.unity`에서 사용자가 Play → **훈련** → `Assets/Scenes/Cyberpunk.unity`. 현재 미저장 작업이 있으면 사용자 보존 방식대로 처리한 뒤 씬을 연다. Codex는 씬 전환/저장을 실행하지 않았다.

**창:** **Tools → CursorDash → 넥서스 수동 검수**. 사용자가 직접 Play한 **훈련**에서만 활성화된다. 현재 체력·표시 수위·눌림·게임판 연결 여부·중심/반경 오차를 보여 준다. 버튼은 현재 라운드의 기존 HP setter/DamageNexus/Retry만 호출한다. 최고기록·설정·저장 프리셋을 초기화/저장하지 않는다. 창을 열기만 하면 피해나 Play가 자동 시작되지 않는다.

1. **컴파일/기본 상태:** Console의 새 C#/셰이더 오류를 먼저 확인한다. 창에 게임판 연결됨, 중심/반경 오차0(부동소수 허용오차1e-4 이내)인지 확인한다. 원형 외형/동작은 그대로이고 육각 한 겹만 약간 밝고 연한지 본다.
2. **체력 최대·중간·낮음:** 창의 **최대100% → 중간50% → 낮음15%** 버튼을 각각 눌러 .3초 이상 관찰한다. 수위가 즉시 해당 높이에 놓이고 가만히 있으며 장식만 기존대로 회전해야 한다. 버튼은 내부 HP setter 호출로 만든 검수 상태다.
3. **단발 피격:** 최대100%로 되돌리고 창의 **기존 훈련 무적**을 끈다. **단발 피해1회**를 누른다. 최대HP의10%가 즉시 깎여 수위.9가 되고 작은 눌림이 .12초 안에 끝나야 한다. 넥서스3부품이 같은 게임판 움직임을 받고 점수/시간/체력 숫자·버튼은 휘거나 움직이지 않아야 한다.
4. **연속 피격:** 다시 최대100% → **연속 피해3회·.04초 간격**을 누른다(실제 간격은 Editor 갱신 주기 영향). 현재HP가 즉시 최신값을 반영하고 마지막 수위.7에서 안정돼야 한다. 이전 높이로 복귀·누적 지연·잔류 파동이 없어야 한다. 이는 기존 DamageNexus 내부 호출이며 실제 노드 충돌 검증과 구분한다.
5. **실제 공격/경계:** 최대100%·훈련 무적 끔 상태에서 기존 생성 버튼으로 원형/육각을 만들어 방치한다. 원형 앞부분과 육각 빔이 기존 본체 경계에 도달할 때 피해가 한 번 발생하는지 본다. 필요하면 기존 Dev의 `debug.boundary`만 켜고 패널을 닫는다. 표시는 빛 번짐/회전 장식 바깥이 아니라 기존 본체 피격 원과 맞아야 한다. 세로/가로 Game View 변경 후에도 맞는지, 기존 이동·잔상·HUD 버튼 입력이 정상인지 확인한다.
6. **HP0/결과/재시도:** 창의 **0%—기존 게임오버 경로**를 누른다. 빈 수위·기존 종료/결과창을 확인한 뒤 **재시도**를 누른다. 체력 최대/눌림0/회전·입력이 복원돼야 한다. 마지막으로 단발 피해 후 pause/resume·Home/재진입도 한 번 확인한다.
7. **종료:** 사용자가 Play를 종료한다. 원본 UI 표시/씬 작업이 그대로인지 확인한다. Play 중 넥서스3 Image.enabled가 꺼져 있는 것은 중복 표시를 피하기 위한 의도된 런타임 상태다. 씬 전체 저장/TMP 초기화가 필요한 구현은 아니다.

피드백은 **최대/중간/낮음 정지 화면 + 단발/연속/0·재시도 짧은 영상 + 검수창 연결/오차 + 새 Console 오류(있을 때)**면 된다. 공통 파괴 타격감의 만족도는 이번 넥서스 표시 검수와 따로 남긴다.
