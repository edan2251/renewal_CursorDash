## 요청과 적용 범위

사용자가 피버 이후 배율 단계별 난이도·레벨디자인 구현을 맡겼으며, 후속으로 **육각 수비와 원형 처치가 이어지는 조합, 육각 연속 수비**를 요청했다. 기존 조사만 하는 단계는 이 요청으로 대체한다. 재미에 대한 최종 판단은 사용자 조작 검수로 남긴다. 아래 수치는 첫 시험 밸런스이며 검수 완료 값이 아니다.

- 현재 배율 ×1/×2/×3/×4를 일반 생성의 단계로 그대로 사용한다. 정상 피버 종료 후 상승, 피격 후 ×1, ×4에서 추가 상승 없음. 별도 점수·누적 피버 가산이나 영구 난이도 저장을 만들지 않는다.
- 기존 PatternReader와 NodeCreator 풀을 확장한다. 새 관리자, 적 종류, 공격·반사·피해·보상 규칙은 없다.
- 바뀌는 것은 일반 노드의 **조합·생성 간격·방향 분산·신규 생성 여유**다. 이미 나온 노드의 공격 시계를 바꾸거나 배율 하락 때문에 지우지 않는다.
- 원형·육각 기본 외형, 등장·충전·변형·발사·파괴, 커서·잔상·반사, 피버 8초/공급/파편/전환, 점수·최고점수, 튜토리얼, 기존 UI 작업을 보존한다.
- 일반 노드 겹침의 전면 개선은 계속 보류다. 이번 새 정상 전투 공급에 한해 최소 간격 검사를 넣었으며, 기존 실습·고스트·수동 생성이나 이미 움직이는 노드를 재배치하지 않는다.

속도 계수는 **생성 대기**에만 적용한다. 원형의 준비/돌진, 육각 회전 박자·발사·레이저 속도, 플레이어 속도에는 적용하지 않는다. 생성 위치는 기존 네 중심을 회전·반전해 사용하고 진행에 따라 각도 범위를 넓힌다. 넥서스에 더 가깝게 만드는 난이도 규칙은 없다.

기존 `spawn.interval` 1.4초는 유지하고 묶음 휴식 .65초를 더한다. 일반 묶음 휴식은 `(spawn.interval + .65) × 간격 계수`, 느린 묶음은 여기에 위 표의 추가 휴식을 더한다. **압박 두 묶음 → 느린 묶음 하나**를 반복한다. 같은 묶음의 즉시 반복을 피하고 방향을 회전·반전하므로 정해진 화면 위치를 외우는 방식은 줄인다.

풀·배치 실패·프레임·피버 진입을 제외하고, 실제 선택 함수로 단계당 30,000묶음을 뽑은 공급 추정은 일반 전투 60초당 약 **34.3 / 41.0 / 48.7 / 57.6개**다. 이전 산술값은 약31.4개다. 이는 실제 분당 공급이나 난이도 측정이 아니며, 피버 시간·히트스톱·Pause 동안 실제 시간 대비 공급은 줄어든다. 기존 노드당 보상은 그대로지만 처치 기회가 많아져 실력에 따라 피버·점수 획득 속도가 빨라질 수 있다.

## 연속 동작을 위한 조합

총12종: 압박10종, 느린 묶음2종. 각 묶음의 `weights` 네 값은 ×1~×4의 선택 가중치이며 0은 해당 단계에서 제외한다.

|---|---|---|
| Opposite circles | ×1 | 반대편 원형 추격 |
| Break then defend | ×1 | 원형 처치 뒤 육각 수비 |
| Defend then turn | ×1 | 육각 예고를 읽고 방향 전환 |
| Three corner sweep | ×2 | 세 방향 원형 연결 |

| Cut across the beam | ×2 | 원형 → 육각 → 옆 원형, 잔상을 놓으며 이동할 기회 |
| Two defense lanes | ×3 | 서로 다른 방향의 육각 두 번 수비 + 원형 |
| Four way exchange | ×3 | 원형/육각 교대와 방향 전환 |
| Guard and sweep | ×3 | 수비 뒤 원형 연속 추격 |
| Late double defense | ×4 | 원형 두 개 뒤 육각 연속 수비 |

| Recovery - read a beam | ×1 | 긴 간격의 원형·육각 |

기존 기본 설정에서 육각 발사는 생성 약2.52초 후, 레이저 비행 설정은 .1초다. 예를 들어 ×2 `Guard and cross`는 육각0초 → 원형.99초 → 원형1.845초로 생성하므로 육각 발사 때 원형이 아직 준비 중이다. **잔상으로 막으면서 원형으로 움직일 수 있는 시간적 겹침**을 만들었으며, 강제 자동 수비나 입력 보정은 없다.

`Two defense lanes`의 두 육각 생성·발사 간격은 ×3에서 .92초, ×4에서 .805초다. ×4의 가장 짧은 묶음 내 육각 간격은 `Late double defense` .735초다. 배치 재시도·설정 Override·히트스톱 등은 실제 간격에 영향을 준다. 이 계산만으로 손 조작 난이도·실제 반사 가능성을 통과 판정하지 않는다.

## 공급과 초기화 안전장치

- 정상 전투 시계 `FeverState.NormalCombatSeconds`를 사용한다. Pause/피버 중 실제 시간만 흘러 생성이 밀리거나 복귀 시 한꺼번에 나오는 예약 큐는 없다.
- 피버 억제 진입·피격·배율 변경 시 아직 생성하지 않은 묶음 단계는 폐기한다. 피버 복귀/피격 후 .8 **일반 전투 초** 동안 다음 공급을 쉰다. 피버 8초에 추가하지 않는다. 반복 피격은 새 시점부터 .8초로 갱신하며 누적하지 않는다.
- 기존 D-029의 남은 패턴 대기 이어가기는 **기존 텍스트 생성 경로에서는 유지**한다. 새 배율 생성 경로는 낡은 압박이 복귀 직후 이어지지 않도록 위 방식으로 대체한다.
- 각 생성에서 기존 실제 외형 범위(원형 약 .425/육각 약 .396world)를 재사용한다. 화면 12~88% 범위 안에 외형 전체가 들어오고, 노드 외곽끼리 .18world, 넥서스 외곽에서 .65world, 현재 커서 머리 외곽에서 .2world의 여유를 둔다. 기존 HUD 겹침 검사도 재사용한다.
- 현재 노드를 지워 자리를 만들지 않는다. 후보24회, .12초 간격으로 최대 .6초까지 재시도 후 해당 생성만 생략한다. 활성 전체/육각 상한과 기존 풀·`spawn.limit` 중 더 낮은 제한을 따른다.
- Retry/Home/사망은 기존 StopAllCoroutines/StartRound 경로로 묶음·시계 관찰·진단 수치를 초기화한다. 튜토리얼/고스트 공급은 새 경로를 사용하지 않는다.

## Unity 조절 위치

`Assets/Resources/CursorDash/MultiplierDifficulty.asset`을 Project 창에서 선택한다. Cyberpunk의 기존 PatternReader에 이 자산이 명시적으로 연결되어 있다.

- `Use Multiplier Encounters`: OFF면 기존 main/sub 텍스트 패턴으로 비교. 다음 라운드 시작부터 적용된다.
- `Tiers` 0~3: 위 표의 배율별 생성 간격, 추가 휴식, 각도/거리 분산, 동시 개수.
- `Patterns`: 조합별 가중치/순서. `Step.Delay`는 이전 노드가 생성된 뒤 다음 생성까지의 초이며 배율 간격 계수를 곱한다. `Kind` 0=원형/1=육각, `Lane` 0=좌상/1=우상/2=우하/3=좌하(화면에 배치할 때 회전·반전).
- 공통 `Phrase Rest Extra`, `Fever Recovery`, `Damage Recovery`, `Placement Wait`, `Node Gap`, `Nexus Clearance`, `Cursor Clearance`로 박자·공간 여유를 조절한다.
- 기존 개발자 `spawn.interval`, `spawn.limit`, `spawn.repeat`, 고정 seed는 재사용한다. `spawn.pattern` 1메인/2서브는 기존 텍스트 비교 경로다. **`spawn.jitter`는 기존/수동 경로용이며 새 조합의 분산은 자산의 Angular/Radial Spread가 담당한다.** 프리셋/JSON API에 자산 값을 중복 추가하지 않았다.
- 편집은 Play를 끄고 자산을 수정한 뒤 새 라운드로 비교하는 것을 권한다. 잘못된 프로필은 경고 후 기존 텍스트 생성으로 돌아간다. 저장 데이터나 최고점은 조절하지 않는다.
- 사용자 Play 중 `Tools → CursorDash → 넥서스 수동 검수`에서 일반 난이도, 조합, 생성/생략 수, 일반 전투 시계를 읽을 수 있다(읽기 전용 표시). 기존 RuntimeUI Snapshot의 `difficulty`에도 같은 정보를 제공한다.

## 수동 확인 순서

1. `Assets/Scenes/Cyberpunk.unity`를 열고 컴파일 오류/프로필 참조를 확인한다. 정상 모드로 시작한다. 개발자 main-only/sub-only 설정이 있다면 기본0인지 확인한다. 저장값 전체 초기화는 하지 않는다.
2. ×1: 첫 공격 예고 길이가 기존과 같은지, 원형 추격·수비 뒤 잠깐 여유가 있는지 확인한다. 진단 창은 숫자/최근 조합 확인용이며 실제 조작 난이도를 대체하지 않는다.
3. 실제 피버 완료 후 ×2: `Guard and cross`/`Cut across the beam`에서 잔상을 놓고 원형으로 이동하는 동작을 확인한다. 동시에 처리할 기회가 있는지와 불가능하게 겹치는 상황을 구분한다.
4. ×3~×4: 서로 다른 방향의 두 육각을 연속 수비하고, 짧은 회복 묶음이 읽히는지 확인한다. ×4에서 여러 번 피버를 마쳐도 더 빨라지지 않아야 한다.
5. 고배율에서 일부러 피격: 배율/진단 단계가1이 되고 다음 생성에 .8전투초 여유가 있는지 확인한다. 기존 활성 노드의 공격이 바뀌거나 사라지면 안 된다. 연속 피격·피버 직후 생성 몰림도 확인한다.
