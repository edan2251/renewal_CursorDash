# 육각 회전 기준 타임라인 — D-040 (2026-10-26)

상태: **IMPLEMENTED_STATIC_AND_UNIT_CHECKED / 수정 후 사용자 Unity 검수 대기**. 기존 개발자 도구를 확장했다. 새 독립 도구/전투 시스템/설치·연결은 만들지 않았다. 자동 Play·Unity 실행·빌드·커밋·push·배포는 하지 않았다. 공개 D-038과 로컬 D-039 변경을 보존했다.

## 이번 결정과 좌표

사용자 확정 요구는 회전 기준 소수 시점/길이 편집, 생성1/3→회전1에2/3→회전2에완충→회전3에변형 **시작**→회전4시작발사, 다음 생성부터 적용, 순서 경고/자동 발사 지연 금지, 기본값 복원/기존 프리셋·JSON 지원이다. D-039의 ‘셋째 끝에 변형 완료’는 최신의 ‘변형 시작’으로 대체한다.

구현 선택은 생성0의 **연속 경과박자** 좌표다. 숫자를 시작/종료 기준과 섞으면 소수 길이와 실제 대기를 일관되게 표현하기 어렵기 때문이다. **실제 첫 링 Outside 1의 시계방향 60도 이동+그 뒤 정지 한 묶음이1박**이다. 360도도 아니고 두 역회전 링의 합도 아니다. 기본 저장값은 이동.4초/정지.4초다.

| 화면상의 사건 | 도구 입력 좌표 | 기본 환산 |
|---|---:|---:|
| 생성/첫 회전 시작 | 0 | 0초 |
| 첫60도 이동 끝 | .5 | .4초 |
| 둘째 이동 시작 | 1 | .8초 |
| 둘째 이동 끝 | 1.5 | 1.2초 |
| 셋째 이동 끝 | 2.5 | 2.0초 |
| 넷째 이동 시작 | 3 | 2.4초 |
| 넷째 이동 끝 | 3.5 | 2.8초 |

따라서 ‘회전4 시작’의 초기 입력은 **3박**이다. 입력4는 다섯 번째 동작 시작이다. 숫자를 임의로 하나 더해 표시하지 않으며 이 표/각도·방향·초를 실제 패널에도 표시한다. 3.5 같은 값은 그대로 입력·저장한다. 소수 좌표의 의미/단위 표시는 이번 구현 선택이며 사용자 검수 대상이다.

`hex.spin`은 전체 박자의 빠르기이므로 **육각에 한해 이동과 정지를 함께 배율로 나눈다**. x1은(.4+.4)=.8초/박, x2는(.2+.2)=.4초/박이다. 이전 D-039는 이동만 빨라져 x2의 주기가.6초였으므로 비1배 프리셋의 전체 템포는 달라진다. 기본1배 모양·방향·움직임은 그대로이며 원형·넥서스 등 다른 Rotator 사용처의 휴지는 바꾸지 않았다.

## 조절 경로와 초기값

사용자가 Unity에서 직접 Play→훈련→**개발자 도구→육각 회전·공격 타이밍**을 연다. 기존 Unity 패널의 위쪽 타임라인/우선 정렬된 수치 행과 하단의 ‘편집→적용’을 사용한다. WebGL 템플릿에도 같은 이름의 바로가기와 접이식 섹션을 연결했지만 이번에 빌드하지 않았으므로 현재 공개 웹에는 반영되지 않았다.

| 항목 | 기존/신규 key | 초기값 | 기본 초 환산 |
|---|---|---:|---:|
| 기준 회전속도 | 기존 hex.spin | 1배 | 1박=.8초 |
| 생성 충전량 | hex.bornCharge | 33.333…% | 생성 순간 |
| 충전1 실행/목표/길이 | hex.charge1.at / target / length | .5박 / 66.666…% / .15박 | .4초 시작, .12초에 걸쳐 .52초 완료 |
| 충전2 실행/목표/길이 | hex.charge2.at / target / length | 1.5박 / 100% / .15박 | 1.2초 시작, 1.32초 완료 |
| 삼각 변형 시작 | hex.morphAt | 2.5박 | 2.0초 |

| 발사 시작 | hex.fireAt | 3박 | 2.4초 |
| 레이저 이동속도 | **기존 hex.attack 재사용** | 화면16.666…경로/초 | 저장 도달시간.06초 |
| 수동 검수 표시 | hex.timelineDebug | 꺼짐 | Dev에서만 즉시 표시 |

충전 시점은 **차오르기 시작하는 순간**, 목표는 누적량이다. 또잉 반응도 해당 길이 안에서 끝나며 그 뒤 목표량을 유지한다. 초기 완성형 대기는2.25~2.40초다. 이전의1.75~2.00초 변형 완료 일정은 최신 요청의 변형 **시작** 일정으로 변경했다. 실제 네이티브 프레임 측정은 하지 않았으며 표는 저장값/사용 수식의 명목 환산이다.

레이저 항목은 중복 속도 설정을 만들지 않도록 UI에서만 기존 도달시간을 역수로 표시한다. **1경로＝발사 원점부터 넥서스 외곽까지의 전체 경로**다. 값이 클수록 빠르며25경로/초를 입력하면 기존 `hex.attack=.04초`로 저장한다. 회전속도를 바꿔도 비행.06초는 자동 변경되지 않는다. 월드/초의 고정 속도를 새로 도입한 것이 아니며, 스폰 거리에 따라 월드/초는 달라지는 기존 방식을 유지한다. JSON은 호환성을 위해 `hex.attack`을 초로 저장하고 변경 보고서에는 화면 속도와 저장 초를 함께 적는다.

기본 발사2.4→외곽도달2.46초다. 잔상 접촉은 경로 위치에 따라 그 사이에 일어나므로 ‘4’는 발사 박자이지 방어 접촉 박자가 아니다. 기존 전체 경로 방어 검사·반사.06초·피해/조준·점수·승인 형상/발사 반동/파괴는 그대로다.

## 적용·충돌·프레임 처리

- 실제 테두리를 움직이는 Rotator 트윈의 `Elapsed(true)`를 같은 주기 길이로 나눠 이벤트를 구동한다. 별도 예약 타이머/Invoke/코루틴은 없다. 기준 링/방향·박자 초는 실행 시 캡처한다. 첫 링이 없으면 둘째를 사용한다.
- 구성은 `Execute`에서 불변 `HexRotationTimeline`으로 한 번 캡처한다. 수치/프리셋 불러오기·기본값 복원은 진행 중인 노드에 적용하지 않는다. **새 육각 생성**으로 비교한다. ‘안전 재생성·시험’은 기존 노드를 지우는 별도 명시 명령이므로 다음 생성 비교에 필수인 버튼이 아니다.
- 누적 충전량 감소/단계 중첩/변형 전 충전 미완료/변형 완료 전 발사 등은 경고한다. 편집 중 임시 충돌은 화면에 남겨 고칠 수 있으며, 충돌한 설정으로 새 육각은 생성하지 않는다. 기존 노드는 유지한다. 발사 시점을 늘리거나 변형 길이를 몰래 자르지 않는다. 충돌 프리셋 저장/가져오기도 거부한다.
- 예: 변형 시작3.5/길이.3125이면 발사를 최소3.8125 이상으로 직접 고쳐야 한다. 발사3.6을 그대로 둔 경우 경고/새 생성 보류이며 실제4.0으로 자동 이동하지 않는다.
- 지난 문턱을 이벤트 비트로 누적해 프레임 하나에 여러 문턱을 건너도 각각1회 처리한다. 충전/변형은 현재 박자에서 해석적으로 복원하며 발사는 한 번이다. Pause는 같은 트윈 시계를 멈춘다. 취소/파괴/비활성화/풀 재사용은 캡처와 이벤트 상태를 초기화해 예약 공격이 남지 않는다. 실제 실행은 렌더 프레임의 양자화를 받는다.
- 회전0/둘 다 없음은 기존 `hex.prepare`를 **3박 환산 기준시간**으로 사용한다. 기본3.5초이면1박=3.5/3초다. 발사 박자를4로 바꾸면 발사까지의 시간도4×3.5/3초가 되며 숨겨진 발사 보정은 없다. 패널에 실제 회전 동기화가 없는 대체 모드라고 표시한다.

## 검수 표시와 저장

‘회전 타임라인 검수 표시’를 켜고 패널을 닫으면 최근 활성 육각 최대4개의 식별자/현재 박자/표시 충전량/단계/다음 사건·남은 박자/캡처된1박 초를 읽을 수 있다. 표시는 기본 꺼짐/Dev 전용이며 읽기 전용으로 게임 조작 기준을 바꾸지 않는다. 패널 안에는 다음 생성 설정과 실행 중인 노드 값을 구분해서 표시한다. 원래의 `Tools→CursorDash→넥서스 수동 검수` 창에도 박자/다음 사건 읽기를 연결했다.

일반 변경은 **현재 세션 임시**다. 기존 ‘프리셋 현재 저장’/Unity의 ‘프리셋 저장’을 눌러야 로컬 저장소에 남는다. 재실행 후 자동 적용하지 않으며 기존 목록 또는 Unity 입력 이름으로 불러온다. 화면에 임시/로컬 저장됨/저장 프리셋 불러옴 상태를 표시한다. 기본값 복원은 타임라인13항목에 한정하는 버튼을 추가했으며 기존 전체/그룹/개별 복원도 유지한다. 사용자 저장 프리셋을 자동으로 덮어쓰거나 삭제하지 않았다.

JSON schemaVersion1은 유지하고 defaultsVersion은 **hex-timeline-v1-20261026**이다. 기존161키에10개를 추가한171키이며 기존 spin/morph/attack을 중복 생성하지 않았다. `hex.morph`만 저장 단위가 초→박으로 바뀌므로 구버전 cp14-v2.1-20261024의 정확한141/157/161키 full을 구분해 환산한다. 이전 변형 초÷새 주기(.8/spin, 회전0이면prepare/3)로 읽고 누락된 새 항목은 기본값으로 보완한다. 임의의 full 누락/알 수 없는 버전·키/순서 충돌은 원자적으로 거부한다. 이전 프리셋 파일/저장값 자체를 바꾸는 작업은 아니다. 비1배의 전체 템포 변화와 충돌 경고를 검수한 뒤 새 이름으로 저장하는 것이 좋다.

## 사용자 검수 순서

1. 사용자가 `Assets/Scenes/Cyberpunk.unity` Play→훈련→개발자 도구. 위 경로로 타임라인을 열고 60도/시계방향·.4+.4초/1박.8초와 회전번호 대응을 읽는다. 새 기본값은 타임라인 전용 복원으로 확인할 수 있다. 기존 사용자 프리셋 삭제/전체 설정 초기화는 필요 없다.
2. 검수 표시를 켜고 패널을 닫은 뒤 새 육각: 생성33.3%→.5박 충전1→1.5박 충전2→2.5박 변형시작→2.8125박 완료→3박(넷째 시작)발사→.06초 비행을 확인한다. 입력은 충전 **시작**이며 길이.15박 뒤 목표에 도달한다.
3. 기존 노드가 진행 중일 때 패널을 열어 morphAt3.5/fireAt4 등으로 조절한다. 현재 노드는 캡처값을 유지하고 새 노드만 새 값을 써야 한다. 변형 소요/각 단계 길이·목표도 소수로 바꾸며 환산 초와 비교한다.
4. 발사를 변형 완료보다 앞에 두면 경고/새 육각 생성 보류가 보여야 한다. 값을 고쳐 새로 생성한다. 코드가 발사를 자동 지연해서는 안 된다. 노드 정리/재사용·변형 중 취소에도 늦은 레이저가 없어야 한다.
5. 회전속도2배에서1박.4초/발사1.2초로 바뀌되 레이저 비행은.06초인지 본다. 속도25경로/초로 바꾸면 새 노드의 비행만.04초여야 한다. 실제 잔상 방어 위치와 반사가 유지되는지도 사용자 입력으로 확인한다.
6. 고유한 새 이름으로 저장→조절→불러오기/전용 기본 복원·JSON/변경 보고서를 확인한다. 에디터 재실행 지속성은 사용자가 기존 미저장 작업을 보호한 뒤 별도로 확인하며 Codex가 재시작하지 않는다. Pause/Resume·Retry/Home 뒤 진단과 예약 공격/상태가 남지 않는지 확인한다.

다음 한 작업은 사용자 Unity 검수다. 노드 겹침 배치, 새 Flash Background 그림/사이버 공간 재구축은 계속 보류한다. 이 도구 제작을 자동 Play·빌드/추가 기능·배포 권한으로 확대하지 않는다.
