## 연결한 전투·상태 처리

- **Closing까지** 기존 일반 전투다. 이때 넥서스가 맞으면 게이지0·배율1로 진입이 취소된다.
- **Entering**이 된 뒤 동기적으로 기존 `NodeCreator.StopNodes()`를 호출한다. 현재 Cyberpunk 풀은 NormalNode/ArrowNode이며 둘의 Reset/OnDisable이 변형·트윈·발사/반환·광선을 정리한다. 생성·정리 통지/피해 경로에 억제 가드를 두어 새 공격/득점을 막는다. 청소는 처치 호출을 사용하지 않는다. legacy DefenceNode/LaserNode는 이 씬/관련 두 프리팹의 대상이 아니다.
- **Entering/Fever/Exiting** 동안 일반 생성과 남은 패턴 대기 시계가 멈춘다. 패턴 코루틴을 끊고 재시작하거나 밀린 적을 한꺼번에 생성하지 않는다. `NormalCombatSeconds`의 절대 목표시각을 유지한다. 현재 게임에 별도 난이도 증가 곡선은 없으므로 새 곡선은 만들지 않았고, 일반 스케줄에 쓰는 시계를 분리했다. 기존 생존 `TimeScore`는 계속 진행한다.
- **Fever**에서 공격하지 않는 흑백 보너스 원형을 곡선 묶음으로 생성한다. 기존 Node의 실행 토큰/Reset 수명을 재사용하는 전용 풀이다. 실제 플레이어 본체 접촉만 처치당 현재 배율 점수를 한 번 준다. 정지 중 생긴 겹침도 재개 후 처리하되 중복 보상하지 않는다. 잔상은 수집하지 않는다. 만료/정리/종료에는 보상 없음. 피버 중 처치는 게이지를 채우지 않는다.
- **Exiting 시작**에 남은 보너스를 무보상 정리한다. 전용 파편 여운은 짧게 정리된다. 정상 종료가 끝난 뒤 한 번만 배율을 올리고 상한4로 반복한다. 취소/HP0/Retry/Home은 완료 횟수/배율 보상을 주지 않고 점선·색·보너스·전용 반응을 복원/해제한다.
- 기존 히트스톱 소유권과 시간 배율 처리에 요청만 전달한다. 보너스/점선/전환/파편은 모두 멈추는 **게임 시계**를 사용한다. 피버 종료 코드가 임의로 `timeScale=1`을 덮거나 사용자의 일시정지를 해제하지 않는다. 기존 Stage 종료 경로가 Retry/Home의 시간·입력을 정리한다.

## 사용자 Unity 검수 — 약5~10분

지금 PC 조작은 필요하지 않다. 가능할 때 진행한다. **Codex는 Play를 실행하지 않았다.**

1. `Assets/Scenes/01.StageSelectScene.unity`를 열고 Console 컴파일 오류를 확인한다. 직접 Play → 훈련으로 들어간다. 실제 전투 씬은 `Assets/Scenes/Cyberpunk.unity`다. 기존 기록 보호를 위해 훈련에서 시작한다.
2. `Tools → CursorDash → 넥서스 수동 검수`에서 원형/육각을 하나씩 생성한 뒤 **만충 → 닫기 시작**을 누른다. 내부 검수 조작은 해당 라운드 기록을 제외한다. 닫기 뒤 기존 적/광선이 사라지고 점수/HP가 정리 때문에 바뀌지 않아야 한다. “정리한 위협/일반 전투초”를 함께 본다.
3. 점선 흡수→응축→빠른 곡선 흑백 방출을 본다. 중앙 HP는 남고 점수/일시정지/설정은 읽혀야 한다. 고정 HUD가 에너지 경계에 따라 잘리거나 전환 중심이 넥서스와 어긋나면 실패다. 후처리 “연결/호출 증가”는 화면 품질의 통과 판정이 아니다.
4. 검수창 대신 Game 뷰에서 보너스 묶음을 직접 연속 통과한다. 흑백 본체 접촉당 현재 배율 점수1회, 게이지는 시간대로 소모, HP는 감소하지 않아야 한다. 잔상만 겹치거나 보너스가 만료될 때 점수가 오르면 실패다. 커서와 궤적이 식별되고 연속 처치가 긴 정지·백색점멸로 막히지 않는지 본다.
5. 8초 유지가 끝나면 보너스 정리→바깥부터 색 회수→점선 전개가 이어지고 **모두 끝난 뒤** x2가 되어야 한다. 일반 전투초는 전환/유지 동안 고정되고 복귀 후 이어져야 한다. 일반 플레이에서는 기존 패턴이 한꺼번에 밀려 나오지 않아야 한다. 생존초는 계속 간다.
6. 만충을 다시 눌러 x2/x3/x4 피버를 반복한다. 각 피버는 시작 배율로 점수 지급, 종료 후만 +1, x4 이후도 x4/반복이 예상 결과다. 보너스 미처치율 조건은 없다.
7. 진입/유지/종료 중 한 번 일시정지·재개하고, 별도 회차에서 **피버 취소 → 일반 복귀**를 누른다. 단계·점선·보너스·소모가 정지/재개되고, 취소는 색/점선/생성을 복원하되 배율을 올리지 않아야 한다. 창의 “단계 끝까지”는 내부 시계 직접 호출이므로 자연스러운 연결감 검수 대신 쓰지 않는다.
8. 훈련의 기존 HP0 버튼/Retry/Home을 각각 시험한다. 완료 보상 없이 보너스/후처리가 사라지고 결과/새 라운드의 시간·입력이 정상이어야 한다. 복귀 후 일반 원형 저지/육각 잔상 방어·파괴/넥서스 마지막 피격을 짧게 확인해 기존 결과가 유지되는지 본다. 일반 넥서스 피격은 기존 무적을 해제하고 확인하면 점수 유지·게이지0·x1이 예상 결과다.

제보하면 좋은 항목: 진입이 느슨한지/방출이 충분히 빠른지, 곡선이 너무 가늘거나 거의 원형인지, 중앙/검정 보너스의 대비, 커서 통과 가독성, 종료 회수와 점선 복귀의 연결, 링 선/화살표/배율 간격. 한 주기 영상이면 연결감 판단에 도움이 된다.

## 보존과 되돌리기

HEAD/main은 `8ceedbb7ead4c2b97417739f62fd7904e1a51497` 그대로다. 시작1,758파일 해시·관련 소스/문서 백업은 `Logs/fever-c-20261025/before.json`, `Before/`에 있다. `D029-only-source-delta.patch`, 신규파일 manifest와 허용 차이 대조는 이번 변경만 분리한다. 게임 원본 씬/프리팹/기존meta·PNG/기존 효과/설정/패키지/참고자료를 되돌리거나 덮어쓰지 않았다. 저장/폐기·TMP 초기화/재시작·설치·전역 설정·자동 Play·빌드·Git 변경 명령 없음. Unity 메모리 저장값·dirty 전후 동일을 실제 측정했다고 주장하지 않는다.

되돌릴 때는 Play 종료와 해당 파일의 후속 사용자 편집 여부를 먼저 확인하고, **이번 delta에 해당하는 구간만** Before와 비교해 복원한다. 신규파일도 manifest 대상만 검토한다. 저장소 전체 reset/clean/restore·전체 백업 덮어쓰기를 사용하지 않는다. 현재는 되돌리지 않았다.
