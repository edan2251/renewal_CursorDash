## 1. 게이지에 따른 바깥 후퇴

기존 실제 경로·분기·배치/등장·구축은 그대로다. 새 CircuitFeverRetreat는 피버 진입 때 로컬 고정 해시로 경로별 시작/완료/속도 곡선을 한 번 정한다. 현재 진행은 **FeverState.Gauge의 `1-Gauge`**만 사용한다. 별도 실시간 타이머·매 프레임 난수/게임 RNG는 없다.

- 구축은 기존 흰 영역/선끝 시계로 유지한다. 해당 묶음이 완전히 구축되기 전에는 후퇴하지 않으며, 완료 뒤 최소 진행.06을 읽기 시간으로 둔다.
- 기본 시작은 피버 진행.18에 최대.30의 분산을 더한다. 완료 시점은 묶음별 순서를 분산해 진행.58~1.0에 고르게 배정한다. 가속 지수1.35에 고정된 묶음별 차이를 준다. 기본8초 기준 가장 이른 시작은 약1.44초, 완료 배정 범위4.64~8초지만 실제 첫 모습은 구축 완료/읽기 조건도 따른다. 실측 시간이 아닌 수치 환산이다.
- 경로의 연결 깊이 front를 줄여 안쪽 선끝이 원래 경로를 거슬러 바깥 루트로 후퇴한다. 분기는 같은 front를 공유하는 연결된 앞부분만 남는다. 전체 알파/전체 스케일을 줄이지 않는다. 완료·강조의 데이터가 남아 있어도 잘린 부분의 메시를 만들지 않으므로 타격/평상시 흐름이 선을 되살리지 않는다.
- 경로별 front는 단조 감소를 보장한다. Pause에는 실제 게이지가 멈춰 같은 front다. 실제 시간 배율/피버 지속시간·점수/공급/판정은 변경하지 않는다.
- 게이지0/Exiting 단계에서는 피버 회로 front를 무조건0으로 반환한다. 회로 중앙 흡입 모델/호출·링 도착 클립·공간과 함께 회수하는 별도 경로는 제거했다. PNG 비교 경로의 옛 중앙 UV 흡입도 더 이상 호출하지 않는다.
- 컬러 회로는 기존 경계에서 다시 뻗어 나오는 방식/속도를 유지한다. 게임오버가 우선이며 이미 줄어든 길이를 상한으로 기존 바깥 후퇴만 실행한다. Exiting 중 사망은 남아 있는 컬러 복원 쪽을 퇴장시키고 피버 회로를 되살리지 않는다.
- 화면비 재구성 시 같은 피버 계획/구축 시작 시계·남은 비율을 복사하여 퇴장을 다시 시작하지 않는다. 새 라운드/다음 피버에서만 새 계획을 캡처한다.

극단적으로 구축 속도를 늦추면 읽기 조건 때문에 후퇴 구간이 짧아질 수 있다. 게이지0 완료를 위해 피버 시간을 늘리지는 않는다. 현재 기본 구축1.8/복원2.1·시차.018은 유지하며 실제 모습은 사용자 검수 대상이다.

## 2. 실제 글자 획만 가리는 마스크

점수 디자인과 실제 값·획득 반응은 수정하지 않는다. **FeverScoreHud.cs/ScoreProjectionPulse/타이포그래피/원본 글꼴은 이번에 변경하지 않았다.** 이미 존재하는 `BackgroundScoreRenderer`에서 TMP의 현재 MeshFilter.sharedMesh와 각 Renderer.localToWorldMatrix, 현재 글꼴 아틀라스/재질 값을 읽는다. 숫자·문자 배치·확대 공식을 새로 계산하거나 메시를 변형/복제하지 않는다.

기존 점수 LateUpdate의 ForceMeshUpdate/OnPreRenderText 획득 반응이 끝난 뒤, 대상 게임판 카메라의 **onPreCull**에서 회로와 글자 마스크를 갱신한다. 현재 점수에 실제 사용되는 정점/UV/변환을 읽기 때문에 점수 변경·자리수·펄스와 같은 프레임을 기준으로 한다. 실제 플레이에서의 최종 정합은 아직 미검수다.

새 CircuitScoreGlyphMask 셰이더는 프로젝트에 있는 TMP_SDF.shader의 face weight/FaceDilate/ScaleRatioA 경계 계산과 실제 아틀라스 alpha를 사용한다. 표시는 원래 재질로 유지하고, **마스크만 정점/FaceColor의 표시 알파를 무시**한다. 숫자가 옅어도 회로 가림은 별도 강도1로 동작한다. 글자 사각형을 채우지 않으므로0/6/8의 구멍과 숫자 사이 공간은 열린다. 배경 색면·노드/커서/넥서스/HUD에는 이 마스크를 적용하지 않는다.

미세한 여유.65/부드러운 경계.75는 게임판 렌더 픽셀 단위이며 마스크 RT 비율로 환산한다. 기본값은 작은 시안값으로 실제 GPU 결과에 맞춘 사용자 조정이 필요하다. 회로 공통 셰이더에서 모든 기본선/에너지/타격/끝 강조의 최종 알파에 같은 가림을 곱한다. 별도 글자 그림·패널·불투명 점수를 추가하지 않는다.

RT는 매 카메라 렌더마다 지우고 실제 현재 메시로 다시 그린다. 이전99와 새100의 가림이 겹쳐 남지 않는다. 원본 점수가 숨겨지거나 비활성/카메라 제외 상태면 가림도 끈다. 마스크 재질/RT/부품 캐시는 재사용하고 자리수 변경만으로 새 리소스를 만들지 않는다. fallback 서브메시/아틀라스 개수가 변할 때만 부품 목록을 갱신한다. 공유 글꼴·원본 재질에 값을 쓰지 않는다.

**WebGL 확인 필요:** 새 SDF 마스크 셰이더 지원/미분 AA, RT 방향/픽셀 정합·여백, 동적 아틀라스/서브메시, 실제 성능·메모리와 해제. 참조 C# 통과나 TTF 오프라인 래스터 검사를 이 결과의 통과로 바꾸지 않는다.

## 6. 사용자 수동 검수

**Assets/Scenes/Cyberpunk.unity**에서 사용자가 Play→훈련, 기존 수동 검수창을 연다. 대비 임시 옵션은 기본OFF로 둔다.

1. 정지/확대 화면에서 두 단계 폭/접합·끝 처리/큰 원 없음과 점수 대비를 확인한다. 두 단계 폭 토글은 이전 폭과의 비교용이다.
2. 점수0/8/10/99→100에서 숫자 획만 가리고 구멍/빈 공간은 열리는지 확인한다. 획 가림 토글로 차이를 본다. 단발/연속·큰 획득 중 확대 축소와 마스크가 동시에 움직이고 이전 숫자가 남지 않아야 한다. 점수 표시 자체의 색/반응/투명도는 같아야 한다.
3. 자연 피버 진입의 바깥 구축→잠깐 읽기→게이지에 맞춘 경로별 바깥 후퇴를 확인한다. 모든 선 동시 삭제/대부분 마지막 잔존·전체 페이드/판 축소가 아니어야 한다.
4. 아직 남은 선에서만 은은한 흐름/강한 실제 타격이 읽히는지, 숫자 뒤에서는 둘 다 가려지고 걷힌 부분이 재생되지 않는지 확인한다.
5. 게이지0에서 피버 회로0·회로 중앙 흡입0인지 확인한다. 그 뒤 기존 검정 노드/흑백 공간/점선 링의 흡입·반동과 컬러 회로 복원이 유지되어야 한다.
6. 피버 도중/게이지0 직후 사망, Pause/Resume·Retry·Home·반복 라운드·여러 화면비에서 두 퇴장이 중복되지 않고 마스크/흐름/리소스가 남지 않는지 본다. 커서/노드/파편·최종파괴/결과·점수 규칙도 기존 결과와 비교한다. 실제 휴대폰/WebGL은 별도 검수다.
