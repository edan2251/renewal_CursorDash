# 다음 테스트용 여섯 항목 수정 — D-024

2026-10-25. **구현·정적 확인 완료 / 사용자 Unity 검수 대기.** 승인 노드 형상과 육각 파괴 연출을 보존했다. 아래의 색·표시순서·짧은 예비·넥서스 바깥 리듬·원형 VFX만 변경했다. 자동 Play/공식 테스트 실행/Unity·WebGL 빌드/커밋/푸시/배포·씬 저장은 하지 않았다.

## 1. 커서와 넥서스 표시 순서

기존 넥서스 합성이 이미 그려진 커서를 덮던 부분을 수정했다. 현재 CursorVisual의 **같은 Sprite·투영·색·스케일·회전/flip**을 읽고, 넥서스가 가린 기여분에만 커서가 앞에 오도록 합성한다. 넥서스 밖에 커서를 한 번 더 그려 투명도가 중복되지 않게 했다. 플레이어 위치/Transform/콜라이더/이동/입력 코드는 바꾸지 않았다.

순서: **게임판 → 기존 배경 플래시 → 넥서스와 그 앞의 커서 → 고정 UI/HUD/설정창**. 커서를 모든 UI보다 위로 강제하지 않는다. 현재 경로는 단순 비패킹 SpriteRenderer용이며 지원되지 않는 커서 구성은 검수창의 앞 표시 연결이 대기로 나타난다. 실제 현재 캐릭터의 연결/가장자리는 Unity에서 확인한다.

## 2. Canvas에 남아 있는 이유와 확인 범위

**의도된 구조**다. `UI/HpBar`, `UI/HpFrame`, `UI/HpCentral`의 기존 배치/스프라이트/참조를 유지하기 위해 Canvas 원본을 남겼다. 실제 화면은 원래3이미지를 읽어 게임판 효과에 합성하고, 중복 표시를 막기 위해 해당 Image.enabled만 Play 중 임시 끈다. Canvas를 삭제하거나 부모를 옮기지 않았다. 종료/렌더 소유권 해제 시 이전 enabled를 복원한다.

| 구분 | 실제 읽은 씬 저장값 / 실행 코드의 연결 |
|---|---|
| Main Camera | Orthographic Size5, depth-1 |
| UI Canvas | **Screen Space–Camera**, 저장 카메라 Main Camera, Sorting Order0 |
| 실행 시 UI | LocalImpactDistortion이 **CursorDash UI camera**를 만들고 depth0/UI layer5만 그리게 연결. UI Canvas 카메라도 이쪽으로 변경 |
| 넥서스3부품 | Main Camera의 NexusGameboard 합성에서 같은 WorldImpact 변위/노출·월드 카메라 흔들림을 적용. HpFrame의 실제 현재 회전도 읽음 |
| 숫자/버튼/설정/결과 HUD | 고정 UI 카메라/기존 Overlay. 넥서스처럼 변형시키지 않음 |
| RemakeHUD | Screen Space–Overlay, 정렬25. Background_Flash는 기존 별도 연결 유지 |
| 넥서스 위치/경계 | 기존 StageManager의 안정된 NexusPosition/Radius에 표시를 정렬. 원본 Rect·실제 공격 경계/HP 규칙은 그대로 |

이것은 **소스 씬과 C# 경로 확인**이다. 이번 세션에는 Unity MCP 읽기 도구가 없었고 UI 조작도 하지 않아 실제 현재 Editor Inspector/Console/GPU를 새로 확인하지 않았다. 사용자가 Play하면 수동창에서 실제 Canvas/카메라·합성 호출 수·커서 연결·중심/반경 오차를 읽어 볼 수 있다. 호출 수는 GPU 성공/시각 승인과 구분한다.

## 3. 육각 테두리 색

첫째는 기존 노랑을 유지한다. 둘째의 이전 흰색18% 혼합을 **기본 RGB의.82배**로 바꿨다. 기준#FFD466이면 약 **#D1AE54**다. 어두운 배경에서 읽히는 금빛 노랑이며 다른 색상 계열로 바꾸지 않았다. 형태·두께·간격·두 회전축·충전/변형은 그대로다. 사용자 Dev 기본색이 있으면 그 색을 기준으로 동일하게 계산한다.

## 4. 육각 발사 예비동작과 시점

| 구간 | 변경 후 기본 명목 시점 |
|---|---|
| 차징3.5초 | 생성→3.50초, 기존 그대로 |
| 기존6꼭짓점 변형.25초 | 3.50→3.75초, 기존 그대로 |
| **반대 방향 당김.05초** | **3.75→3.80초** |
| **멈칫.03초** | **3.80→3.83초** |
| 레이저 발사/기존 도달.25초 | **3.83→4.08초** |
| 반사 반환 | 기존.06초 |

**발사 시작은3.75→3.83초, 추가.08초**다. 표는 게임시간의 명목값이며 프레임 양자화/일시정지/히트스톱으로 실제 관찰 시점은 달라질 수 있다. Codex가 Play로 실측한 숫자가 아니다.

몸체만 실제 발사 방향의 반대로 최종 반경/스케일의8%(기본 약 **.02944월드**) 물러나 잠깐 유지하고, 발사 때 원래 위치로 풀린다. 루트 빔 원점/도달시간/반사·피해는 바꾸지 않았다. 예비 중에는 최종6꼭짓점/충전1을 유지하고 **실제 발사 후에만 뒤→앞 에너지 소모**를 시작한다.

새 Inspector `preFireDuration=.08`, `preFireRecoilRatio=.08`은 이번 검수용 임시값이다. 기존 Scene/Prefab YAML에 이 값을 일괄 저장하지 않았다. 현재는 Inspector 전용이며 기존161키 JSON에는 추가하지 않았다.

예비는 코루틴/예약 콜백 없이 ArrowNode의 Warning 하위 상태에서 처리한다. Reset/비활성화/파괴/Retry/Home/사망은 상태를 지우고 몸체/빔을 복원한다. 예비 중 취소된 노드가 나중에 발사될 예약 작업은 없다. pause는 진행만 멈추고 resume 시 남은 예비를 이어 간다.

## 5. 넥서스 가장 바깥 테두리

실제 저장값은 **HpFrame -360도/4초(평균90도/초)**였다. HpFrame만 기존 방향을 유지하며 다음 결정적 리듬으로 바꿨다.

| 구간 | 회전량 | 가감속 이동 | 휴지 |
|---|---:|---:|---:|
| 1 | 30도 | .24초 | .22초 |
| 2 | 45도 | .28초 | .34초 |
| 3 | 60도 | .30초 | .16초 |

한 리듬1.54초, 평균87.66도/초다. 총 회전량을 늘리지 않고 순간 속도만 높여 짧게 돌고 쉰다. 시작/끝 속도가0인 부드러운 가감속이며 프레임 무작위/방향 반전은 없다. 기존 방향-1과 시작 시 `nexus.spin` 배율을 존중한다. pause/히트스톱은 기존 게임시간과 함께 멈춘다.

바깥의 기존 Rotator만 런타임 소유권을 넘긴다. **HpCentral(+360도/3초), 원형/육각 Rotator는 유지**했다. 공유 Rotator 소스 변경은 읽기 전용 DirectionSign getter 한 줄뿐이다. 새 리듬 컴포넌트 해제 시 이전 enabled를 복원한다.

## 6. 원형 전용 파괴 VFX

승인된 **ImpactFragments.cs/ImpactFlat.shader는 그대로**다. 원형만 CircularBreakVfx로 보내며 육각의 초기화·움직임·셰이더·기본값은 변경하지 않았다. 공통 화면 셰이크/왜곡/사운드/히트스톱 경로와 값도 유지했다.

- 실제 접촉 실루엣이 약 **.014초**에 진행 방향으로30% 눌리고 옆으로10% 벌어진 뒤 약.030초에 사라진다.
- 접촉점에 작은 방향성 섬광 **.035초**. 기존 섬광 끄기/배율을 따른다.
- **.012초 뒤** 앞쪽 주 파편2개가 기본 속도의2.05~2.6배로 튀고 나머지는 더 작고 느리게 따른다. 전체 방향은 실제 incoming이다.
- 크기·회전·속도를 다르게 하고 파괴 한 번마다 고정한 변형을 쓴다. 지수 감속14~22/s로 빠르게 느려지며 회전도 감쇠한다.
- 기본 개수8/기존 수명.28초·색·설정을 재사용하고 최대12개다. 작은 크기 상한/경계 AA/축소·소멸을 유지한다. 다량 파편/블러/대칭 방사 폭발은 추가하지 않았다.

원형 VFX는 이번 **시안/사용자 검수 대기**다. 육각 파괴가 좋아졌다는 사용자 승인을 원형이나 공통 타격감까지 확대하지 않는다.

## Unity 검수 순서

**시작:** 사용자가 `Assets/Scenes/01.StageSelectScene.unity`에서 Play → **훈련(Cyberpunk)**. Console의 새 C#/셰이더 오류부터 확인한다. Tools → CursorDash → **넥서스 수동 검수** 창은 스크롤 가능하다. 원본 Canvas/카메라·게임판 카메라·합성 호출 증가·커서 연결·경계 오차를 확인한다.

1. **커서/Nexus:** 직접 커서를 넥서스 중앙과 바깥 테두리 위로 지나가게 한다. 가려지지 않아야 하고 이동/충돌은 그대로여야 한다. 설정창을 열면 커서가 설정창 위로 강제로 덮지 않아야 한다. 캐릭터 Sprite/색/방향을 바꾸어 쓰는 경우도 확인한다.
2. **넥서스 렌더/경계:** 훈련 무적을 끄고 단발 피해나 실제 노드 방치로 피격시킨다. 본체/수위/회전 장식이 함께 움직이고 숫자·버튼은 안정돼야 한다. 창의 중심/반경 오차는1e-4 이내, 기존 debug.boundary는 본체 경계와 일치해야 한다. 화면비 변경 후에도 확인한다. 내부 피해 버튼 검수와 실제 노드 충돌/입력은 구분한다.
3. **육각 외형/예비:** 기존 생성 버튼으로 육각1개를 만든다. 어두운 노랑 한 겹·승인 형태/역회전은 유지하고, 충전→6꼭짓점 변형 완료→짧은 반대 반동/멈칫→발사 순서여야 한다. 예비 중 에너지가 줄거나 빔이 먼저 보이면 실패다. 발사 후 뒤→앞 소모·도달/반사 속도와 **승인 파괴 연출**도 비교한다.
4. **예비 중 취소:** Editor Pause/Step으로 수동창의 ‘변형 완료·발사 예비동작’을 관찰한다. 그때 해당 육각 루트를 비활성화하거나 훈련을 재시도/Home으로 나간다. 재개 후 늦게 발사되는 빔/피해가 없어야 한다. 예비 중 pause/resume은 몸체가 멈췄다가 정상 발사로 이어져야 한다. 같은 풀 노드 재사용 때 위치/형태/에너지/테두리가 복원돼야 한다.
5. **바깥 리듬:** 다른 조작 없이 여러 구간을 본다. 바깥 HpFrame만 짧게 가속·감속 후 쉬고 간격이 달라야 한다. HpCentral/노드는 이전 회전, 방향은 계속 같아야 한다. pause/resume·HP0·재시도도 확인한다.
6. **원형 VFX:** 좌/우/위/아래 방향으로 접근해 충전·변형 중 원형을 파괴한다. 커서가 박히는 짧은 압축/섬광, 앞쪽 주 파편·속도/크기/회전 차이·빠른 감속을 본다. 대칭 꽃/큰 덩어리/과한 개수·블러가 없어야 한다. 섬광0 옵션·연속 접촉·pause/Retry/Home 후 잔류/중복도 확인한다. 육각 파괴는 기존 결과와 같아야 한다.

가능하면 겹침 화면1장·육각 충전→발사/취소 영상·바깥 리듬 약5초·원형 접촉 짧은 영상을 남긴다. Codex는 이번 자동 캡처/Play를 수행하지 않았다. 이 결과와 절차를 전달한 뒤 중단한다.
