## 복원한 외형

기준은 A 원본인 `Assets/Art/Nodes/Cyberpunk/Types/Cyberpunk_AttackNode/`의 Central/Inside/Outside/Outside_2 PNG와 현재 ArrowNode 프리팹의 참조·스케일이다. 이전 B 스프라이트 시트를 대신 쓰지 않았다. 원본 PNG/.meta/프리팹/씬을 변경하지 않았다.

두 Outside PNG를 반알파 윤곽으로 읽어 **각6개 끊어진 꼭짓점, 두 겹/총12조각·250꼭짓점**의 벡터 도형으로 옮겼다. .25원본픽셀 이내로 단순화하고 원래 PPU100/피벗·간격·두께를 반영했다. 넓은 블러/픽셀 깨짐은 복제하지 않고 승인 원형과 같은 경계 AA 셰이더를 **별도 머티리얼로 재사용**한다. 원형 파일을 수정하지 않았다.

색은 기존 노랑 **#FFD466**을 유지한다. 두 겹이 겹칠 때 한 선처럼 합쳐 보이지 않도록 첫째는 기본색, 둘째는 같은 RGB의 **.82배 명도**다. 같은 색상·채도의 노란 계열이며 분홍색으로 복귀하지 않는다. 현재 사용자 Dev 색은 기존대로 존중한다. 새 색 슬라이더나 프리셋은 추가하지 않았다.

회전은 새 트윈을 만들지 않고 기존 `Node/Outside 1`, `Outside 2`의 실제 Transform을 각각 따른다. 프리팹 저장값은 -/+60도/.4초이고 기존 `hex.spin` 배율이 적용된다. 두 개의 원본 위상·반대 회전·변형 중 흡수/축소를 그대로 읽는다. Cyberpunk 씬에는 해당 회전/공격 시간 필드의 override가 없음을 정적으로 확인했다. 실제 Editor 메모리 값 실측과는 다르다.

## Unity 검수 절차

1. 현재 Unity에서 코드 반영이 끝나면 Console의 새 C#/셰이더 오류를 확인한다. 오류가 있으면 전문을 전달하고 Play를 보류한다. 전체 저장/TMP 초기화/씬 재생성은 필요 없다.
2. 평소 시작 경로로 Play → **훈련**에 들어간다. 기존 Dev 실험값이 있으면 현재 보고서/JSON을 보관하고, 검수 기준만 확인한다: `hex.color=#FFD466`, `hex.spin=1`, `visual.outline=.035`, `visual.core=0`. 기록/저장 프리셋/일반 설정을 삭제하지 않는다. 타격감 프리셋이나 수치는 이번 검수에서 추가 변경하지 않는다.
3. 기존 육각 생성 버튼으로 하나를 놓고 충전을 본다. **두 겹의 끊어진 테두리가 서로 반대로 회전하는지**, 각6개 조각·간격/본체 대비 크기가 A와 비슷한지, 둘째의 조금 어두운 노랑으로 두 겹이 구분되는지 확인한다. 내부는 중앙에서 확대되고 독립 중앙점은 없어야 한다.
4. 충전이 끝나면6꼭짓점을 유지하며 발사 방향으로 돌아가는지 본다. 테두리가 흡수/소멸하고 기존 빔이 발사되며, 에너지가 **넥서스 반대쪽(뒤)부터 발사구(앞)** 방향으로 빠져야 한다. 노드를 넥서스의 위/아래/좌/우에 생성해 방향을 짧게 확인한다.
5. 기존 잔상으로 방어·반사해서 반환 빔 도착 때 파괴되는지 확인한다. 한 번은 방치해 기존 넥서스 피해 흐름도 본다. 타격감 만족도는 외형 승인과 별도로 남긴다.
6. 충전 중 일시정지/재개를 한 번 확인하고, Retry/Home 후 새 육각에 두 겹·충전/회전이 정상 복원되는지 본다. 여러 번 생성/반사 후 테두리가 중복되거나 이전 형태가 남으면 실패다. 승인 원형 외형이 그대로인지도 한 번 확인한 뒤 Play를 종료한다.

피드백은 **육각 충전 정지 화면 1장 + 충전→변형→발사의 짧은 영상 + 새 Console 오류(있을 때)**면 된다. 이번 범위는 여기서 멈추며 타격감·넥서스나 다음 기능을 자동 진행하지 않는다.
